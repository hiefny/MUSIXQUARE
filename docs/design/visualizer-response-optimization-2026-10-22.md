## 저음 반응이 잘 보이지 않았던 이유와 수정

기존 보호기는 원형 비주얼라이저의 `(level / 255)^2.5` 값을 밝기 최대 6%에
곱했다. 낮은·중간 크기의 저음이 한 번 더 압축되어, 저음 대역의 평균 입력이
−60 dB인 합성 조건에서는 정상상태 밝기 상승이 약 0.58%였다. 코드상 공통 원인을
확인한 것이며, 사용자 환경에서 재생한 모든 소스의 신호 연결을 재현한 것은 아니다.

보호기는 0–140 Hz 평균에서 작은 노이즈를 제외하고 제곱근 응답을 적용한다.
최대 상승은 16%, attack 60 ms / release 400 ms로 제한한다. 같은 −60 dB 합성
입력에서는 약 9.3% 상승한다. 빠른 밝기 전환을 피하면서 일반 크기의 저음에서도
반응을 키우는 의도된 표현 변경이다. 시계 글자는 이미 밝아 배경보다 변화가 작다.

음소거와 저음이 없는 소스는 반응하지 않는다. analyser는 기존대로 master gain
뒤에 연결되므로 앱 볼륨도 반응 크기에 영향을 준다. YouTube iframe의 소리는
분석할 수 없으며 기존 보호기 진입 제한을 유지한다. 오디오 라우팅·출력·지연은
변경하지 않았다.

## 적용한 최적화와 사용자에게 보이는 차이

- 공유 raw FFT를 최대 약 60회/초 읽고 magnitude 변환도 공유한다. 소비자별
  smoothing은 실제 경과 시간에 따라 진행해 화면 보호기와 원형/스펙트럼 모드가
  서로의 잔상 계수를 바꾸지 않는다. 120 Hz에서도 분석 사이의 프레임은 계속
  보간한다. 분석 간격으로 인해 새 입력을 반영하는 시점에는 최대 약 한 분석
  간격의 차이가 생길 수 있다.
- 보호기는 약 30회/초 분석하며 위상을 유지해 59.94/60/120 Hz의 반올림 때문에
  빈도가 약 20회/초로 떨어지는 문제를 피한다.
- 화면 보호기의 420 ms 진입 전환이 끝난 뒤에만 뒤 Canvas를 중단한다. 닫기
  전환 전에 재개한다. 숨김 탭·화면 밖·크기 0도 중단하고, 같은 크기로 복귀하면
  시작 warmup을 반복하지 않는다. 일시정지로 보존한 화면은 따로 유지한다.
- OS의 동작 줄이기를 켜면 정지 화면을 표시한다. 모드 선택, 키보드 조작,
  설정 저장과 일시정지 화면은 유지한다.
- 저음은 140 Hz 미만, 고음은 7.5–20 kHz로 고정한다. 기존 고음 대역은 sample
  rate에 따라 가청 범위를 벗어났으므로 원 크기와 반응하는 악기가 달라진다.
- 스펙트럼은 각 로그 구간의 peak를 표시한다. 건너뛰던 FFT bin의 좁은 피크가
  나타나므로 일부 곡선이 이전보다 높아진다. 순수한 속도 개선으로 분류하지 않는다.
- grid gradient, 곡선 중간 좌표와 활성 점 배열을 재사용한다. 동일한 점 입력에서
  그리는 모양과 기존 dither/fallback을 유지한다.
- 활성 스펙트럼 모듈은 해당 모드를 선택할 때 로드한다. 초기 정지 화면은 즉시
  그린다. 최초 미캐시 선택에는 작은 추가 다운로드 대기가 생길 수 있으며, 로딩
  중 모드 전환·숨김·일시정지 뒤 오래된 loop를 시작하지 않는다. 선택 모듈은
  service-worker app-shell에 포함해 설치가 끝난 뒤 오프라인에서도 사용할 수 있다.

## 검증 결과

전체 typecheck·lint·format 검사 통과. Lazy 분리 뒤 변경한 제품·테스트·tooling
TypeScript도 다시 통과했다. 집중 단위 테스트 7개 파일 160/160 통과.
프로덕션 빌드의 eager JS는 gzip 479.9 KiB로 기존 한도와 5% reserve를 유지한다.
SW app-shell 102개 자산(주입 47개, 시작 Worker 1개) 검사가 통과했다.

첫 전체 단위 실행에서는 별도 릴리스 fixture가 과부하 중 30초 timeout에 걸렸고,
bootstrap의 cache query를 v764로 바꾸지 않은 누락을 찾았다. query를 수정한 뒤
해당 두 파일 137/137이 통과했다. 최종 전체 실행 결과와 browser 결과는 아래에
별도로 기록한다. 실패를 처음부터 통과한 것으로 취급하지 않는다.

- Lazy 파일 분리 전 실제 구현의 Canvas renderer를 기존 SHA와 비교: Chromium 24/24,
  WebKit 24/24 RGBA 완전 일치. 두 크기, DPR 1/2/3, 밝은/어두운 테마,
  dither/gradient fallback을 포함한다. **동일한 점 입력** 비교이며 새 peak 집계나
  음악 반응 곡선이 기존과 같다는 의미는 아니다.
- Lazy 분리 전 Chromium 격리 모듈 통합 36/36, 페이지 오류 0. 실제 48 kHz analyser에
  80 Hz oscillator(gain 0.01)를 연결했다. 표시 중 약 30–31 draw/0.5초,
  완전 가림 뒤 0 draw와 22–23 분석/0.75초를 기록했다. 열기·닫기 전환에서는
  12–13 draw/0.2초로 이어졌다. 보호기 iframe의 밝기는 1.044였다.
- 위 격리 검사에서 `document.hidden`은 headless 환경의 제약 때문에 getter와
  visibilitychange 이벤트로 모사했다. DOM display:none, 미디어 쿼리,
  CSS opacity 전환, Canvas와 analyser는 실제 브라우저 동작을 사용했다.
  file/system 모드 표시는 상태 전환이며 실제 시스템 캡처를 뜻하지 않는다.

## 범위와 남은 확인

새 npm 의존성·서버 프로토콜·데이터 스키마·비밀·바인딩 변경은 없다. App만의
호환 가능한 후보이며 배포 승인을 포함하지 않는다. 로컬/PR 검증은 exact-main
CI release candidate가 아니다. 운영 버전과 기존 복구 floor는 그대로 유지한다.

물리 Android/iOS의 가청 재생·전력·GPU 부하와 사용자의 실제 음악에 대한 시각
체감은 미검증이다. Windows Playwright WebKit에서는 AudioContext가 제공되지
않아 WebKit의 Web Audio 수명주기를 검증하지 못했다. Canvas 비교 통과를 실제
Safari 오디오 호환성 통과로 확대하지 않는다. 전체 기기에서 절충이 없다고
보장하지 않으며, 위 의도된 표현·최초 로딩 차이를 함께 검토해야 한다.
