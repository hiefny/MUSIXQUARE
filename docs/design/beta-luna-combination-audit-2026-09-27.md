### 실제로 확인한 불변 조건

- 현재 곡으로 승격된 파일 전송을 끝낸 뒤 후속 프리로드를 시작한다.
  교체된 연결의 ACK가 새 연결의 전송 소유권을 바꾸지 않는다.
- 겹친 수신 세션에서 선택된 현재 파일의 바이트가 남고, 그 파일이
  디코더 진입점에 한 번 도달한다. 이전 파일이 먼저 완성됐다면 그 ACK도 정상이다.
- 재접속 이후 이전 연결은 물리적 참가자 관리 권한을 행사하지 못한다.
  인증된 같은 참가자의 권한 일정과 신규 입장이 기존 재생 상태를 오염시키지 않는다.
- PRO 공유 제어의 옛 API 응답은 새 세션의 lease를 덮거나 지우지 않는다.
  새 세션에서 정상 획득한 lease를 대조군으로 확인했다.
- 검색 C가 화면에 표시된 뒤 늦게 도착하는 A/B 응답까지 포함해,
  현재 검색만 결과·선택·로딩·추가 버튼 상태를 소유한다.
- 데모의 최신 재생/일시정지 의도와 재진입 세대가 유지된다. 옛 비동기 작업의
  콜백이 새 세대의 곡·로딩·재생 상태를 바꾸지 않는다.

## ASTRA 재검증과 오탐 처리

ASTRA는 주요 프로브 6개 파일을 별도 실행하여 **1,082개 통과**를 확인했다.
이는 위 1,080개와 비정상 순서 대조군 2개의 재실행이며 총계에 다시 더하지
않는다. 보조 함수 168개는 Luna 최종 실행과 소스 검토 근거다.

초기 프로브의 실패를 바로 제품 결함으로 인정하지 않았다. 확인된 문제는 다음과 같다.

| 최초 의심 | 검토 결과 |
| --- | --- |
| 재접속 후 관리자 권한이 사라짐 | 익명 연결의 권한을 새 연결에 보존하지 않는 기존 정책이었다. 같은 인증 참가자 재접속 검증에는 인증 identity 경계를 구성해야 함 |
| 수신 종료·데모 재진입이 연속 실행에서만 누락 | 사례들이 같은 가상 peer의 프로토콜 요청 한도를 공유했다. 사례마다 한도를 초기화한 뒤 전체 실행 통과 |
| 이전 파일 ACK 발생 | 이전 파일이 정상 완성된 순서라면 ACK가 맞음. 현재 파일의 소유권·바이트·디코더 진입을 별도로 판정 |
| 검색 로딩 상태 불일치 | 아직 B가 진행 중인데 로딩이 없어야 한다고 기대한 검사 오류. 당시 요청 소유권에 맞게 수정 |
| PRO 새 lease 획득 실패 | 이전 사례의 API 모사 구현이 다음 사례에 남은 fixture 문제. 독립화 후 새 lease 대조군 및 옛 응답 순서 검증 통과 |

초기 단계에서 실제 경로를 실행하지 않는 조합, 같은 guard의 무의미한
반복, 모사 결과를 제품 동작으로 간주하는 검사는 보완하거나 보조 검사로
분리했다. 최종 통과는 제품 수정을 해서 얻은 결과가 아니다.

## 재현 자료와 검증 한계

실행 가능한 프로브·사례별 manifest·로그는 로컬의 무시된 디렉터리
`scratch/luna-combination-audit-2026-09-27/`에 있다. 저장소에는 이 기록만
남기므로 다른 checkout에서 문서만으로 바로 테스트를 실행할 수는 없다.

각 `media/`, `rooms/`, `surface/`에는 `scenario-manifest.json`과 `report.md`가
있으며 각 사례의 초기 상태·동작 순서·결과·제약을 기록했다. 최종 로그는
`media/final-matrix.log`, `rooms/run.log`, `surface/search-matrix.log`,
`surface/demo-matrix.log`다. ASTRA 재실행 로그는 루트의
`astra-{sender,receiver,standard,pro,search}-rerun.log` 및
`astra-demo-verified.log`다. 실패했던 초기 데모 로그도 따로 보존했다.

로컬 프로브가 남아 있는 환경에서는 고정 Node로 다음 형태로 재실행한다.

```powershell
& './scratch/beta-upgrade-2026-09-09/node-v24.20.0-win-x64/node.exe' node_modules/vitest/vitest.mjs run --config scratch/luna-combination-audit-2026-09-27/media/vitest.config.mts --maxWorkers=1 --reporter=dot
```

나머지는 config를 `rooms/vitest.config.ts`, `surface/vitest.config.mts`로 바꾼다.
각 config는 해당 디렉터리만 포함하며 저장소의 외부 네트워크 차단 setup을 사용한다.

**실제 브라우저·기기·네트워크·코덱을 통과했다는 증거는 아니다.**
이번에는 전체 기존 단위 테스트, E2E, 실서비스나 장기 세션을 실행하지 않았다.
특히 다음은 통과 수로 덮지 않는다.

- 실제 iPhone Safari/PWA·Android·WebRTC 연결/ICE 전환·출력 싱크 정밀도.
- 대용량 파일 네이티브/하이브리드 디코딩, 메모리 한계, 실제 YouTube iframe.
- PRO 서버 재생 PREPARE/COMMIT/CANCEL, SFU/직결 전송, 시계 보정 gate의 통합 동작.
- 데모 옛 디코더 자체의 버퍼 쓰기. 지연 디코더는 부작용 없는 Promise이며,
  이번 검사는 그 이후 모드 콜백의 세대 보호에 한정한다.
- 채팅·귓말·설정은 기존 근거의 소스 검토만 했다. 계정·운영 DB·봇 등
  나머지 도메인 전체를 새로 실행한 전수 감사가 아니다.

검증된 조합에서는 새 결함을 찾지 못했다는 결론이다. 잔여 검증 필요와
확정 미수정 결함을 혼동하지 않는다. 기존 B01–D01 해결 상태는 유지하고,
이번 탐사에서 추가된 확정 미해결 항목은 없다.

제품·추적 테스트·버전·캐시·의존성·DB/Worker 계약은 바꾸지 않았다.
베타에 QA 문서만 기록하며 main·프로덕션 배포·원격 워크플로 설정은 변경하지 않는다.
