## 오너 지시와 결정

- **지시(2026-10-27 07:15 KST).** 두 감사(UI 이슈, 힌트 문구)의 추천 방향을 전부 자동으로 반영해 한 묶음으로
  배포한다. 오너가 정할 일로 남았던 곳은 추천안을 고른다. 오너는 자리를 비웠다.
- **간격 측정 기준(정정).** 글자 잉크가 아니라 버튼 표면(배경·테두리) 가장자리 사이를 잰다. 기준은 휴대폰 재생
  탭의 채팅 상자와 동기화·미디어 버튼 사이 간격이다.
- **간격과 높이.** 대화상자, 재생 탭, 시작 화면 모두 버튼 표면 사이 12px, 알약 높이 56px. 디자인시스템 정책(간격
  값은 레시피이고 루트 토큰으로 내보내지 않는다)을 지키고, 같은 값을 계약 테스트로 묶는다.
- **두 버튼만 있는 창.** 지금처럼 글자 길이대로 나눈다(`flex: 1 1 max-content`). 같은 폭으로 맞추지 않는다. 2+1
  구조의 줄바꿈도 그대로다.
- **버튼 글자.** 모든 액션 버튼 라벨은 색만 다르다(15px / 700 / 줄 높이 1.25 / 자간 기본). 계정 삭제는 공용 보조
  버튼 + 위험 색 변형이다. 위험 글자색은 새 색이 아니라 새 역할 토큰 `--danger-foreground`다.
- **호버.** 노트북 자세와 스튜디오(태블릿) 자세의 호버를 근본적으로 같게 한다.
- **− 아이콘.** 펼치기 화살표 옆에서 길어 보이는 것을 고친다.
- **이월 주석.** 5B 릴리스 준비 리뷰의 낮음 지적 하나(SFU 능력 표지를 읽는 방장 범위)를 이 열차에서 고친다.
- **힌트.** 툴팁은 '지금 못 쓰는 이유'와 '누르면 시작되는 모드'에만 둔다. 아이콘 이름 툴팁은 두지 않는다.
- **문구 규칙(추천안을 고름).** 이름과 힌트는 명사형으로 끝낸다. 사유 힌트는 명사형 상태구(`재생 제어 권한 필요`)이고
  누르면 뜨는 토스트 문장은 그대로다. `삭제하기` → `삭제`, `다음으로` → `다음`. 반복 이름은 `반복 안 함` /
  `Repeat current track`. 화면 라벨 묶음(데모 단계 칩, `초대 링크 복사`)도 같은 꼴로. 설정 동기화 표시 이름은
  기존 키 `설정 동기화`.
- **위험 빨강, 첫 결정(U8, 오후).** 기본 라이트 테마의 위험 글자색을 `#d70015`로 하고, 앱의 빨강을 모두 찾아
  글자·아이콘 빨강은 역할 하나로, 세션 나가기 배경도 `--control-danger` 계열로, 디자인시스템 UI 키트도 토큰을
  읽게, 안 쓰는 `text-link` 버튼 종류는 삭제, 수동 싱크 초기화·완료도 어댑티브 쌍으로.
- **위험 빨강, 두 번째 결정(U10, 저녁, 첫 결정의 `#d70015`를 대체).** 오너가 U8 전후 이미지를 보고 정했다. 기본
  라이트·다크 테마에서는 대비를 쫓지 않는다(더 어두운 빨강의 모양을 받아들이지 않음). 대비는 대비 강화 옵션이 맡는다.
  오너가 고른 안: 기본 테마의 빨강은 운영의 `#ff3b30`이고, 그래도 빨간 글자·아이콘은 모두 `--danger-foreground` 역할
  하나를 읽으므로 오류 글자와 배지 빨강(`#ff4d4f`, `#ef4444`)도 `#ff3b30`이 된다. 버튼은 9.0.18과 똑같이 보여야 한다.
  대비 강화 팔레트는 U8 조정과 4.5:1 계약을 그대로 둔다.
- **최종 검토 뒤 결정(U11, 2026-10-27 밤).** 최종 검토 뒤 오너가 셋을 정했다.
  (1) 계정 삭제는 기본 라이트·다크 테마에서 9.0.18의 색을 쓴다. 평소 바탕 `rgba(239, 68, 68, 0.1)`, 호버 16%, 누름
  20%라 호버와 누름에서 다시 진해진다. 이 열차에서 지키는 것은 라벨의 역할 `--danger-foreground`(기본 테마 `#ff3b30`),
  공용 15px / 700 라벨 토큰, 56px 알약과 12px 간격이다. 대비 강화 팔레트는 이 열차의 조정 그대로다. 운영 값과 같은
  값의 토큰이 있으면 그 토큰을, 없으면 운영 값을 쓴다(새 팔레트 없음). 오너 항목 1이 이 결정으로 닫힌다.
  (2) Chromium 79 TV에서 `:where()` 호버 관문 때문에 호버 효과가 없는 것을 받아들인다(known-accepted, 코드 변경
  없음). 오너 항목 9가 닫힌다. (3) 이 열차는 영어 화면 글을 바꾸지 않는다. 화면에도 보이는 `common.youtube_video`의
  en 값은 9.0.18의 `YouTube Video`로 되돌린다.
- **순서.** 오너 부재 중 이 열차가 아직 구현 중이라 바로 배포 원칙(2026-10-25)에 따라 PRO 방 영수증 보관 시간 열차가
  먼저 9.0.18 / v791로 나갔다. 이 열차는 9.0.19 / v792로 뒤따르고, Phase 5.5는 그 뒤 오너 승인을 기다린다.

지킨 규칙: 메인 디자인시스템 토큰만 쓴다(새 팔레트 없음), 새 컴포넌트·배너 없음, 글자 굵기 최대 700, 한국어
UI는 '트랙', 토스트는 마침표 없이 문장마다 줄바꿈(대화상자는 문장), 기본 라이트·다크 테마는 대비를 쫓지 않고 4.5:1
계약은 대비 강화 팔레트만, 빨간 글자·아이콘은 모두 `--danger-foreground`(기본 테마 `#ff3b30`), 선택 블록 변형 모델
유지(알약은 반지름을 지키고 행별 CSS 모양 바꾸기 없음), E2E는 CI에 넣지 않고 로컬 게이트로 돌린다. 릴리스 준비
라운드(아래 QA 라운드 5)가 bump 뒤에 이 규칙들을 다시 확인했다.

### U1 대화상자 간격 12px과 알약 56px (추천표 1·2)

- 커밋: 테스트 `dde623dd` → 구현 `31a6e32e`, 리뷰 반영 테스트 `a3350ee9` → 구현 `6c407dea`.
- 바꾼 것: `.adaptive-action-group` gap 12px(모든 대화상자, 계정 창, 이동·복사 창), 로그아웃 상태 닫기 위 12px,
  `.dialog-primary`, `.dialog-secondary`, 계정 삭제, Google 버튼 56px. 디자인시스템 대화상자 샘플, 토스트·대화상자
  미리보기 카드, 로그인 완료 카드도 같은 값. 아주 짧은 화면의 압축(높이 350px 이하 계정 창 6px과 44px, 480px 이하
  단계형 창 48px)은 이름 붙은 예외로 남는다.
- 리뷰가 찾은 틈: YouTube 링크 창의 취소·재생 줄은 `.setup-card-mt-8-row` 유틸리티의 10px(`@layer components`)이
  `.ob-actions`(`@layer base`)를 이겨 10px로 남았다. 유틸리티에서 gap을 빼 공용 12px을 받게 했다. 높이 350px 이하에서
  로그아웃 상태 닫기 위는 로그인 상태 간격(6px)을 따른다.
- 테스트 먼저: `dde623dd`(런타임은 부모 `1ff7fdf2`)에서 3 files / 5 failed, 130 passed(이 보고서를 쓰며 커밋을 꺼내
  다시 돌린 값). `a3350ee9`는 `31a6e32e`에서 2 failed, 6 passed.
- 검증(`6c407dea`): 단위 전체 681 files / 16,060, 가드, `tsc`, `typecheck:tests`, `check:workers`, lint, format, build와
  초기 전송 예산(entry 841.3 KiB raw / 247.5 KiB gzip, eager JS 454.9 KiB gzip), 로컬 E2E 8개 파일 70개(adaptive-actions,
  dialog-locale-layout, design-system-page, rtl-player-layout, component-cascade, youtube-search-interactions,
  demo-settings, playlist-edit-mode). 42개 언어 × 375 / 390px 측정에서 모든 간격 12px, 모든 알약 56px, 오류 0.

  568x320 30 → 24px). 계정 통계도 844x390, 740x360에서 6px 줄어든다. 둘 다 이전부터 스크롤되던 상태다.

## 연결 끊김 배지

오너가 이 배지가 무엇인지 물었다. U8 빨강 비교 이미지에 처음 나온 배지라 화면에서 본 적이 없는 것이 맞다. 운영에서
한 번도 보일 수 없던 분기였다.

- 어디: 설정 오디오 패널 끝의 '연결된 기기' 목록(`#device-list`, `renderDeviceList` in `src/ui/settings.ts`)이 줄마다
  상태 배지를 그렸다. 상태가 `connected`면 초록 '연결됨'(`common.connected`), 아니면 빨간 '연결 끊김'
  (`common.disconnected`, `.d-status.inactive`, `#ff4d4f`)이었다. 이 빨강이 U8의 빨강 목록에 걸려 이름이 드러났다.
- 왜 못 보나 1: 목록을 만드는 곳이 모두 연결된 기기만 보낸다. 방장의 `broadcastDeviceList`(`src/network/peer-state.ts`)는
  `status === 'connected'`인 피어만 넣고, PRO 프레즌스 투영은 모든 참가자를 `connected`로 만들며, 게스트는 방장의 목록을
  그대로 그린다. 그래서 빨간 분기에 들어갈 줄이 없다.
- 왜 못 보나 2: 이 목록 칸(`.settings-device-section`) 자체가 휴대폰(`css/style.css`)과 데스크톱(`css/desktop.css`)
  모두 `display: none`이다. 초록 '연결됨' 배지도 화면과 화면 낭독기에 나오지 않는다. 연결 UI는 연결 탭과 데스크톱
  연결 하위 탭이 맡는다.
- 처리(U10, `75a36a39` → `cc3b0209`): 빨간 분기, `.d-status.inactive` 규칙, 42개 언어의 `common.disconnected`를 지웠다.
  이제 모든 줄이 '연결됨' 하나를 그린다. 테스트가 방장 방송은 연결 중인 피어를 빼고, PRO 프레즌스 줄은 모두 연결됨이고,
  설정 목록에 끊김 문구와 클래스가 없음을 고정한다.
- 남긴 것: 숨은 칸 전체(`renderDeviceList`, `.d-status`, `common.connected`, `settings.devices_title`)를 지울지는 오너가
  정할 일이다. 이번 지시가 '연결됨 배지는 그대로'여서 손대지 않았다.

## main 합침

`2eaaf4c5`에서 origin/main `6a23c46e`(운영 9.0.18 / v791)를 합쳤다. 충돌은 6개 파일이고 양쪽을 다 살렸다.

| 파일                                             | 처리                                                                                                                                                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/rooms/permission-feedback.ts`               | main: 토스트 매퍼를 비공개로 두고 대기 중이면 "확인 중" 토스트를 주는 `roomCapabilityFeedbackMessage`. 이 브랜치: 힌트 표와 `roomCapabilityRequiredTip`. 둘 다 유지                         |
| `src/ui/player-controls.ts`, `src/ui/seekbar.ts` | 이 브랜치의 힌트 도우미와 한 구절 힌트, 볼륨 그룹의 고정 이름과 설명을 유지. main이 넣은 '대기 답이 오면 다시 그리기' 연결(역할 표지, 방장 연결, 연결 중, 세션 시작)은 자동 병합으로 들어옴 |
| 테스트 3개                                       | import 합집합. 언어 상태 테스트는 main의 대기·확정 나눔 유지                                                                                                                                |

main의 새 문자열과 규칙을 이 열차의 규칙 아래로 가져온 방법:

- **CSS.** main이 그사이 더한 규칙은 대화상자 `max-height: 100%` 한 줄뿐이라 이 열차의 토큰(위험 글자색, 위험 색조,
  12px, 56px, 호버 관문)을 적용할 새 규칙이 없었다. 합친 뒤 가드(빨강 하드코딩, 라벨 토큰, 리듬, 호버 관문)가 모두 통과한다.
- **대화상자와 토스트 문장.** main의 `pro.upload.*` 사유는 대화상자 문장, `pro.room_state_limit`은 토스트라 힌트 규칙
  대상이 아니다. 토스트 정책 테스트(마침표 없음, 문장마다 줄바꿈)를 통과한다.
- **힌트에 들어간 토스트 문장.** #503이 재생·미디어·재생 위치 바의 title에 대기 중 "확인 중" 토스트 두 문장을 넣었고,
  잠긴 볼륨 그룹의 이름도 그 토스트로 바꿨다. 힌트 규칙은 토스트 문장을 title에 쓰지 못하게 한다. 합침 커밋은 이 브랜치의
  확정 힌트를 택했고, 그 차이로 main 테스트 7개가 실패한 채로 남겨 다음 두 커밋이 고쳤다.
  - `roomCapabilityFeedbackTip`이 `roomCapabilityRequiredTip`을 대체한다. 일반 방 방장의 역할 투영이나 PRO 계정 답이
    대기 중이면 확인 중 힌트, 그 뒤에는 확정 힌트다. 누르면 뜨는 토스트는 main 문장 그대로다.
  - 새 키 셋 × 42개 언어: `player.playback_control_checking_tip`, `player.media_management_checking_tip`,
    `player.admin_permission_checking_tip`(ko `재생 제어 권한 확인 중` / `미디어 관리 권한 확인 중` / `관리자 권한 확인 중`,
    en `Checking playback control permission` / `Checking media management permission` / `Checking administrator
permissions`). 각 언어의 "확인 중" 토스트 첫 줄을 한 구절로 썼다. ko·ja는 확정 힌트처럼 존댓말 끝을 떼고, bg·cs·pl·ru·uk·it는
    그 언어 상태 문구의 명사구를 쓴다.
  - 재생·이전·다음, 미디어, 재생 위치 바, 반복·셔플, 볼륨 그룹(설명 포함), 잠긴 음향 설정 그룹이 모두 이 함수를 읽는다.
    반복·셔플도 역할 표지·방장 연결·연결 중·세션 시작에서 다시 그린다.
  - 문구 정책 스캔이 지역 도우미 안의 import 표까지 따라간다. 토스트 매퍼의 표도 등록해, 도우미를 거쳐 토스트가 힌트로
    들어가면 실패한다. 합침 시점의 스캔은 이것을 못 잡았다.
- **5B 이월 주석.** main에 들어온 5B 코드 위에서 적용했다(`31766f7c`). 적용 시점 운영 바닥은 여전히 787이라 문구 그대로다.

버전 거울은 main의 9.0.18 / v791 그대로다.

## 사용자가 알아챌 변화

- 모든 대화상자 버튼이 2px 커지고(54 → 56px) 버튼 사이가 2px 넓어진다(10 → 12px). 계정 창, 이동·복사 창, 확인 창, YouTube
  링크 창, 디자인시스템 샘플이 같다. 일부 언어는 좁은 폰에서 계정 쌍이 두 줄이 된다(영어 360px 포함, 위 13개).
- 시작 화면 버튼, 설정 액션 줄, 초대 링크 복사, 모두 선택, 재생 탭 동기화·미디어 라벨, 세션 나가기 라벨이 600 → 700.
  계정 삭제와 수동 싱크 초기화·완료가 14 → 15px.
- 계정 삭제: 라벨 빨강 `#ef4444` → `#ff3b30`. 바탕과 호버·누름 색조는 기본 두 테마에서 9.0.18과 같다(`#ef4444` 10% /
  16% / 20%, 호버와 누름에서 진해짐, 누름은 0.97 축소도). 터치 뒤 남는 호버 배경 없음, 라이트에서 보이던 테두리 없음.
  대비 강화에서는 바탕이 그 팔레트의 `--control-danger` 하나다.
- 빨간 오류 글자와 내보내기·해제·지우기·업로드 취소 아이콘이 `#ff3b30` 하나가 된다. 라이트 대비 강화에서는 모두
  `#a4001d`이고, 나가기·공유 중지·데모 나가기 색조가 그 팔레트의 짙은 색조가 된다. 세션 나가기와 공유 중지의 기본 테마
  색은 9.0.18과 같다.
- 서피스 랩톱 스튜디오 같은 컨버터블의 스튜디오 자세에서도 마우스·펜을 움직이면 호버가 켜진다. 터치 탭 뒤에는 호버 모양이
  남지 않는다. 재생목록 − 는 호버와 키보드 포커스에서 파랗고, 펼치기 화살표도 키보드 포커스에서 파랗다. 선택 모드에서
  줄 호버가 순서 손잡이를 꺼내지 않는다. 2021년 LG webOS TV 같은 Chromium 79 엔진에서는 호버 효과가 없다(오너 수용,
  허용 위험 #20).
- 재생목록 − 가 짧고(약 9.2px) 화살표와 같은 굵기다.
- 툴팁: 이름만 반복하던 툴팁이 사라지고(선택 막대 동작, 입력칸 지우기, 현재 트랙으로 이동, 관리자 부여·해제, 데모 다음,
  초대 코드), 잠긴 반복·셔플·볼륨·음향 설정에 사유 한 구절이 뜨며, 권한 확인 중에는 확인 중 구절이 뜬다. − 는 선택 모드
  밖에서만 모드 진입 힌트가 뜬다.
- 한국어 화면 글: 기기 내보내기 확인 창 제목 `기기 내보내기`, 내보내진 쪽 창 `방에서 내보내졌어요` / `방장이 이 방에서
내보냈어요.`, 권한 창 `멤버 내보내기`와 그 토스트, `{{name}} 님의 권한`, 데모 단계 칩 `1. 기기 연결`, `2. 역할 설정`,
  `4. 체험 종료`, 연결 탭 `초대 링크 복사`, 채팅 `/d` 설명 `기기 내보내기`. ko 언어 파일에서 바뀐 값 가운데
  화면 글은 이것뿐이다(U11 점검: 그 밖의 바뀐 값과 지운 키는 aria-label이나 title).
- 영어 화면 글은 바뀌지 않는다. `common.youtube_video`는 iframe title이면서 아티스트가 없는 YouTube 트랙의 재생
  부제(`getTrackSubtitle`, `src/ui/player-controls.ts`)와 제목이 빈 YouTube 검색 결과의 대체 제목(`src/youtube/search.ts`)
  이라, 문장 대소문자 규칙(#40b)에서 빼고 9.0.18의 `YouTube Video`를 그대로 둔다(U11에서 되돌림).
- 화면 낭독기: 명사형 이름, 고정된 토글 이름과 상태, − 이름 `{{title}} 선택`, 선택 개수를 한 번 읽음, 선택 막대가 개수로
  이름 붙음, 캐러셀 점·이퀄라이저 대역·화면 보호기·초대 QR의 번역된 이름.
- 수동 싱크 초기화·완료가 56px, 12px 간격, 긴 언어는 두 줄.
- 숨은 설정 기기 목록의 '연결 끊김' 배지 삭제는 화면에서 바뀌는 것이 없다.

## 바꾸지 않은 것과 오너가 정할 것

1. **계정 삭제 배경(해결, U11).** 최종 검토는 계정 삭제만 9.0.18과 다르다고 남겼다(U2의 공용 보조 버튼 + 위험 색 변형:
   평소 `--control-danger`, 호버·누름 색조 없음, 글자 15px). 오너가 저녁 결정 때 본 U8 비교 이미지의 '적용 전' 칸도
   9.0.18이 아니라 U2 모양이었다. 오너가 최종 검토 뒤 정했다: 기본 라이트·다크의 평소·호버·누름 표면은 9.0.18 값
   (`rgba(239, 68, 68, 0.1)`, 16%, 20%)이고, 라벨 역할 `--danger-foreground`, 15px / 700 라벨 토큰, 56px 알약, 12px 간격은
   이 열차 값이며, 대비 강화는 이 열차의 조정 그대로다(위 U11). 9.0.18과 남은 차이는 라벨 `#ef4444` → `#ff3b30`, 글자
   14 → 15px, 높이 54 → 56px, 관문 아래 호버다. 세션 나가기 라벨 굵기 600 → 700은 U2 결정 그대로다.
2. 이동·복사 창의 아주 짧은 화면 압축 여부(U1 기록).
3. 언어 목록·선택지 줄의 라이트 호버(U3 보류).
4. 잠긴 음향 설정 그룹의 설명 읽기. 리버브·EQ·가상 효과 그룹은 사유를 설명 맨 앞에 두므로 화면 낭독기가
   `Only room admins can change audio settings Adjust the sound's reverb and resonance.`처럼 한 문장으로 이어 읽는다.
   제대로 고치려면 설명용 문장 키를 두는 문구 후속이다.
5. 숨은 설정 기기 목록 칸 전체 삭제(위 '연결 끊김 배지' 절).
6. 추천표에서 손대지 않은 넷(이동·복사 창 제목, 2+1 창 아래 버튼 무게, 첫 화면 16px, 알약 호버·눌림 통일).
7. 문구 후속: 랜딩 내비 이름(Worker 배포 필요), 화면 라벨 후보(방 연결 완료 문구, 닉네임 바꾸기, 계정 배지 Label in
   Name), 미디어 고르기 창 어휘('미디어 재생'과 '미디어 추가'가 같은 창을 엶).
8. 말라얄람어 수동 싱크 패널의 높이 360px 이하 압축(다음 증분 후보).
9. **Chromium 79 TV 호버 효과 없음(해결: 오너 수용, U11).** 2021년 LG webOS의 매직 리모컨 포인터 같은 Chromium 79
   엔진은 `:where()` 관문을 읽지 못해 호버 규칙만 버리고, `guard:legacy-tv-build`가 포커스·누름 규칙을 지킨다. 9.0.18에서는
   `@media (hover: hover)` 규칙이 TV에서도 적용됐다. 오너가 이 절충을 받아들였고 코드는 바꾸지 않았다
   ([허용 위험 #20](../known-accepted.md#20-chromium-79-tvs-show-no-hover-effects)).

이전부터 있던 흰 글자 대비(채팅 안 읽음 배지 3.76:1, 채팅 YouTube 카드 3.96 / 3.34:1)와 이벤트 페이지 오류 글자(라이트
3.57:1)는 기본 테마 대비를 쫓지 않는다는 결정에 따라 오너 항목에서 뺐다.

## 되돌리기

- 앱만 바뀐다. 저장 데이터, 통신 모양, 계약 표지, 저장 키, 서버 경로는 그대로다. 호버 플래그는 런타임 속성이라 남는 것이
  없다.
- 기본은 hotfix 절차대로 더 높은 SemVer와 캐시 epoch로 9.0.18 코드를 다시 내는 것이다(9.0.20 / v793 이상). App Worker를
  9.0.18 버전(`c7a0d90f`)으로 CLI 롤백해도 최소 빌드 787 위라 바닥을 내릴 필요가 없다.
- 섞인 버전: 9.0.18과 9.0.19는 같은 방에서 그대로 함께 쓸 수 있다(바뀐 것은 화면과 접근성 이름뿐).

- Chromium 79 실제 TV: 정적 검사(`guard:legacy-tv-build`)만 있다.

2. 트랙 몇 개를 선택해 이동·복사 창: 버튼 간격, − 길이와 굵기가 옆 펼치기 화살표와 어울리는지, − 를 누르면 체크로 바뀌는
   모습.
3. 세션 나가기 확인 창 같은 확인 창 하나: 두 버튼이 글자 길이대로 나뉘는지.
4. 재생 탭: 동기화·미디어 라벨 굵기, 미디어 공유 중 공유 중지와 연결 탭 세션 나가기의 빨강·배경이 9.0.18과 같은지(누를 때
   세션 나가기가 조금 더 진해짐).
5. 서피스 랩톱 스튜디오: 노트북 자세와 스튜디오 자세에서 재생목록 − 파란 호버, 줄 호버, 시작 화면 캐러셀이 마우스를 올리면
   멈추는지. 손가락으로 탭한 뒤 호버 모양이 남지 않는지. 선택 모드에서 줄에 마우스를 올려도 순서 손잡이가 나오지 않는지.
6. 키보드 Tab으로 재생목록 − 와 펼치기 화살표에 가면 파랗게 되는지.
7. 게스트로 들어가 잠긴 재생·미디어·반복·셔플·볼륨·음향 설정에 마우스를 올려 사유 한 구절이 뜨는지, 누르면 토스트는 전처럼
   문장인지. 방에 막 들어갔을 때 '권한 확인 중' 구절이 잠깐 보이는지.
8. 휴대폰 화면 낭독기(VoiceOver나 TalkBack)로 − 를 누를 때 '{{트랙}} 선택'과 선택 개수가 한 번씩 읽히는지.
9. 설정에서 대비 강화를 켜고(라이트) 빨간 글자와 나가기 버튼 색.
10. 설정의 수동 싱크 창: 초기화·완료 버튼. 가능하면 언어를 말라얄람어로 바꿔 두 줄로 들어가는지.
11. 영어로 바꾼 작은 폰(폭 360px)에서 계정 창의 `Sign out` / `Delete account`가 두 줄이 되는 모습이 괜찮은지.
12. 한국어 문구: 기기 내보내기 확인 창 제목, 내보내진 쪽의 창, 데모 단계 칩, `초대 링크 복사`.
13. 오래된 LG webOS TV가 있으면: 호버 효과가 없고(받아들인 한계, 허용 위험 #20) 포커스·누름은 그대로인지.
