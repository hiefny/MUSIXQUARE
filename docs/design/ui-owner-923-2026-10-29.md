## 오너 결정 (2026-10-29)

- **7 ja 대기 알약.** 시작 화면 뒤로 옆 알약의 일본어 `common.wait`를 'お待ちください...'에서 '準備中...'로 바꾼다. 같은
  키를 쓰는 곳(게스트 대기 알약, 계정 창 로딩 문장, YouTube 검색 바쁨 라벨)도 같은 말이 된다.
- **8 연결 끊김 창 본문.** 방 코드가 있는 게스트에게는 '다시 시작하면 이 방에 다시 들어갈 수 있어요'로 끝나는 게스트용
  본문을 쓴다(오너 문구, 영어 'Restart to join this room again.'). 방장과 코드 없는 게스트는 지금 본문 그대로다. 조사의
  선택 항목(두 끊김 창의 겹침 막기)은 겹침이 재현되지 않아 이 열차에 넣지 않았다.
- **9·12 세션 나가기.** 같은 '세션 나가기' 확인 세 가지(연결 탭 [취소 \| 확인], 로고 [남아있기 \| 확인], 뒤로가기
  [남아있기 \| 나가기])를 [남아있기 \| 나가기] 하나로 맞추고, 나가기는 계정 삭제와 같은 위험 색조다. 방장 응답 없음 창의
  세션 나가기도 같은 색조다. 위치, 제목, 본문, 첫 포커스(남아있기, 계속 기다리기)는 그대로다.
- **10 PRO 방 새로고침 필요 뒤의 뒤로.** 눌러도 반응 없던 뒤로를 다른 새로고침 필요 경로와 같은 복구 함수로 살린다.
- **13·19 제목.** ja·zh 제목은 낱말 가운데서 끊지 않고, 어떤 제목도 상자 밖으로 넘치지 않으며, 넘치던 ta 방장 응답 없음
  제목은 짧은 문구로 바꾼다.
- **17 데모 4단계 [체험 종료 \| 트랙 정보].** 아이콘은 20px로 고정하고, 넘치던 ta와 ml 체험 종료 글을 줄인다. 아이콘을
  고정하면 nb 'Sporinformasjon'이 320px에서 0.77px 넘쳐 CI 시험 'demo finish pair no worse than 9.0.18'이 실패하므로 nb
  `demo.track_info`를 'Sporinfo'로 줄이는 것도 오너가 승인했다(구현 뒤 검토가 물은 것). PR CI(Linux 글꼴)에서는 sv 'Spårinformation'이 320px에서 2.50px 넘쳐(Windows 글꼴에서는 들어감) sv도 'Spårinfo'로 줄였고 오너가 승인했다(테스트 먼저 `1d1369e9`, 수정 `96a9a8f0`). 첫 PR CI 40865852264의 Critical browser gate가 이 한 건으로 실패했다.
- **18 데모 머리글.** 9.0.20이 더한 머리글 맨 앞 나가기 버튼을 지우고(조사안은 버튼을 두고 말줄임만 더하는 것이었음),
  머리글에는 앨범명 없는 짧은 트랙 이름을 쓴다. 1 ~ 3단계는 뒤로와 Esc로 나가고 4단계 체험 종료는 그대로다.
- **11 수동 싱크.** 패널을 9.0.20 전처럼 [초기화 \| 완료]로 되돌린다(완료는 오른쪽 주 버튼, 라벨은 완료 그대로). 이때
  오너가 '나가기는 왼쪽' 규칙을 대화상자의 [취소 \| 행동] 짝으로 좁혔다. 패널을 마치는 주 행동(완료)은 오른쪽에 둔다.
- **1a와 6은 시험만.** 1a: PRO 방 등록 라벨 시험을 F5 전 전폭 배치의 22자 규칙 대신 실제 짝 배치 측정으로 지킨다(화면
  그대로). 6: 740x361 두 열 사이드바 시험은 탭 상자의 투명 여백 대신 마지막 탭 알약과 계정 배지 사이를 잰다(화면 그대로).
- **배포 원칙(2026-10-25).** 자동 게이트(로컬 검사, 리뷰, PR CI, 자동 코드 리뷰, exact-main CI, 릴리스 smoke)가
  통과하면 따로 묻지 않고 배포한다. 기기 근거는 게이트가 아니다.

## 확인하지 않은 것

- 실기기와 iOS Safari: 모든 측정이 Windows의 Chromium과 WebKit이다. WebKit에는 WebRTC가 없어 방 안 화면은 옮겨 그린 값이다.
- Safari ja 제목: auto-phrase가 없는 Safari에서 일본어 제목은 개선이 없다(측정 20건 그대로). 단계형 PIN 제목의 ja·zh 끊김은
  남긴 규칙이다.
- ja `pro.claim_account_conflict_title`: Chromium 320px에서 2 → 3줄을 실제 PRO 계정 충돌 흐름에서는 보지 않았다(측정만).
- 원어민 검토: 새 게스트 문장(한국어 밖 41개 언어), ja '準備中...', ta·ml 체험 종료와 ta 제목, nb 'Sporinfo'.
- 8번 실제 흐름: 게스트의 신호 연결과 방장 연결이 모두 끊긴 상태의 창은 재현하지 못했다(단위 시험과 마크업 렌더).
- Linux 글꼴: Linux Chromium(CI)과 Linux 글꼴의 줄 수는 재지 않았다.
- E2E: WebKit 레인 전체, 9.0.23 런타임의 전체 직렬 E2E, 화면 낭독기.
- 방장 응답 없음 창의 첫 프레임: 나가기 확인 셋은 프레임마다 쟀고, 이 창은 같은 `_openDialog` 경로라 단위 시험으로만 봤다.
- 운영: 배포 전이라 운영 브라우저의 업데이트 창과 운영 화면은 아직 보지 않았다.
