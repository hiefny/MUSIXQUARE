## 1. 오너 결정

오너의 말은 옮기지 않고 뜻만 적는다.

- **2026-11-04 새벽, `/debug` 창의 COPY 버튼:** `/debug` 창의 글을 복사하는 버튼을 승인했고, 9.0.37에는 넣지 않고 뒤 열차로 미뤘다
  ([9.0.37 보고서 §1](app-9-0-37-train-2026-11-04.md#1-오너-결정)).
- **2026-11-04 오후, 글자 크기 정리:** 앱 전체에 넓은 13단계 글자 크기표를 두자는 제안은 앱의 박자와 오너가 정한 위계를 바꾸므로 취소했다.
  대신 소수점이 붙은 고정 크기만 정리하고, 화면 폭에 따라 커지는 크기(`clamp()`와 `vw`)에서 나오는 소수점은 그대로 둔다. 그 범위에서: 데모
  둘러보기의 글자는 앱에서 같은 역할을 하는 글자의 크기를 따르고(단계 제목은 시작 화면 회전판의 제목, 단계 글은 회전판의 설명, 트랙 이름은
  재생목록의 트랙 이름), 채팅의 '#1'은 9px이며, 화면에 나오지 않는 규칙은 지운다.
- **같은 날 오후, 첫 사진과 질문을 본 뒤:** 데모 역할 버튼은 양 끝이 정수인 `clamp(12px, 1vw, 14px)`로 한다(첫 사진의 14px 고정은 몇 폭에서
  2026-10-29의 4px 여유 규칙을 깼음, §3.1). 데스크톱의 COPY 버튼은 휴대폰처럼 좁게(350px) 가운데에 두고, 읽히지 않는 `--setup-guide-desc` 선언
  둘도 지운다.
- **2026-11-04 21:20 KST 무렵, 휴대폰 시작 화면 스크롤 막대:** 휴대폰 시작 화면의 스크롤 막대가 화면 끝이 아니라 글 옆에 서는 것을 고치는 안의
  사진(지금과 바꾼 뒤, 다섯 크기)을 보고 승인했고, 다섯 부분을 모두 9.0.38 한 App 업데이트로 내기로 했다.
- **배포 규칙:** 바로 배포 원칙(2026-10-25)대로 자동 관문(로컬 전체 관문, PR CI, 자동 코드 리뷰, exact-main CI, 릴리스 smoke)이 모두
  통과하면 따로 묻지 않고 내고, 업데이트 열차는 오너가 깨어 있을 때 dispatch한다(2026-10-31). 기기 확인은 게이트가 아니다.

## 3. (1) 데모 둘러보기의 넓은 화면 글자와 역할 버튼 [화면 바뀜]

### 3.1 의도한 변경

## 6. (4) `/debug` 창의 COPY 버튼 [화면 바뀜]

### 6.1 의도한 변경

- `/debug console`, `/debug sync`, `/debug screen`, `/debug sa`(시스템 오디오)의 글 창 아래에 COPY 버튼 하나. 누르면 그 순간 화면에 보이는 글을
  그 누름 안에서 복사하고 단추가 COPIED로 바뀐다(두 길 모두 실패하면 COPY FAILED). 토스트가 창 밑에 깔리므로 결과는 단추에 보인다.
- **복사:** Clipboard API 쓰기를 클릭 처리기에서 await 전에 시작한다. iPhone Safari가 창을 열 때의 복사를 거절하는 것은 그 복사가 지연 불러오기와
  await 뒤에 시작해 명령을 보낸 누름이 이미 끝났기 때문이다[추론: 코드와 WebKit의 규칙에서, 실기기에서 재지 않음]. API가 없거나 던지면 숨은 읽기 전용 textarea와 `execCommand('copy')`로 바로, 쓰기가 거절되면 거절 처리기에서 복사한다
  (WebKit은 거절을 그 사건 안에서 바로 하고, Chromium은 뒤 작업에서 하지만 사용자 활성 상태를 약 5초 지님). 채팅 모듈은 `src/ui/dom.ts`를 불러올
  수 없어 같은 방식의 textarea 복사를 따로 둔다. 창을 열 때의 자동 복사는 그대로라 데스크톱 Edge는 여전히 열 때 복사한다.
- **빈 글과 늦은 복사:** 첫 표본 전(`/debug sa`는 RTCStats를 기다림)의 빈 글은 복사하지 않고 라벨은 COPY 그대로다. 누른 복사가 있으면 열 때의
  복사가 나중에 끝나도 그 글을 덮지 않는다.
- **초점과 클릭:** 닫을 때 초점이 창 안에 있으면(Windows의 Chromium과 Firefox는 누른 단추에 초점을 줌) 창을 열 때 초점이 있던 곳(대개 채팅 칸)으로
  돌려준다(페이지로 떨어지면 다음 스페이스가 재생을 바꿈). COPY 누름은 페이지까지 가서 앱의 단추 소리가 나고, 누르면 닫히는 창(`/debug screen`,
  `/debug sa`)도 COPY 누름에는 닫히지 않는다.
- **크기:** 720px 미만은 글 아래 줄을 채우는 350 × 42 단추다(390 × 844에서 y 745 ~ 787, 화면 안). 720px부터는 줄이 366px(안쪽 8px 포함)로 창
  가운데에 서서 단추가 휴대폰처럼 350px이다(1440 × 900에서 x 545 ~ 895. 고치기 전 갈래에서는 1400px 알약이었음). 가로로 든 휴대폰도 폭이 720px
  이상이면 다른 720px 규칙처럼 좁은 단추다(844 × 390에서 804 → 350px). 단추 옆 빈 곳을 누르면 창 바탕을 누른 것과 같다. 같은 클래스를 쓰는 온보딩
  진단 화면은 그대로다. 단추 글자 COPY, COPIED, COPY FAILED는 개발자용 창의 다른 글처럼 영어이고 번역 문자열을 더하지 않았다.
- 타이머, 재시도, 시한, 수명 흐름은 더하지 않았다.

## 7. (5) 휴대폰 시작 화면 스크롤 막대 [화면 바뀜]

- **(C) iPhone의 COPY, 키보드가 올라온 채:** iPhone Safari로 방에 들어가 채팅 칸에 `/debug console`을 치고 보내기를 누른 뒤 키보드를 내리지 않은
  채로 화면을 찍고, COPY를 누른 뒤 메모에 붙여넣는다. 데스크톱 Chromium에서도 같은 것을 한 번(COPY를 누르고 붙여넣기). 그 결과가 release-record §2
  '후속 작업과 유지 결정'의 iPhone `/debug console` 복사 항목을 닫거나 잇는다. 판정(확인하는 사람에게 건네지 않음): COPY가 키보드 위로 보이고, 누른
  뒤 COPIED이며, 붙여넣은 글이 창의 글과 같아야 한다. COPY가 키보드에 가리면 `/debug` 창이 열릴 때 터치 기기에서 채팅 칸의 초점을 빼거나 단추 줄을
  보이는 자리에 두는 고침을 뒤 열차에 적는다.
- **(D) 짧은 휴대폰의 시작 화면 스크롤:** 세로가 짧은 휴대폰(예: 화면 높이 568 ~ 667px 급, 또는 Safari 도구 막대가 보이는 상태)과 휴대폰을 가로로
  든 상태에서 시작, 방 참여, 방 만들기 화면을 위아래로 스크롤하고, 화면 양옆 빈 곳에서도 한 번씩 밀어 본다. 판정(건네지 않음): 막대가 화면 오른쪽
  끝에 서고, 글과 단추가 예전 자리이며, 양옆에서 민 것도 칸을 움직여야 한다.
- 실패하면: 먼저 새 빌드인지 다시 보고, 증상의 부분((1) ~ (5))을 적고 §11대로 앞으로 고치기(9.0.39 / v812 이상)나, 급할 때만 명시적으로 검토한

## 16. 하지 않은 것과 확인하지 않은 것

- push, PR, PR CI, 자동 코드 리뷰, exact-main CI, 배포, 운영 확인, 머지 뒤 Full E2E는 하지 않았다(릴리스 단계 몫). 버전 올리기 머리의 전체 로컬
  관문도 아직이다(§14 1).
- 실기기(iPhone Safari·iPad, Android, 여러 데스크톱 브라우저)는 다섯 부분 모두 없다. 특히 iPhone에서 COPY가 클립보드에 글을 넣는지(Playwright의
  WebKit은 창을 열 때의 복사도 되어 iPhone의 거절을 재현하지 않음), 키보드가 올라온 채 COPY가 보이는지, 짧은 휴대폰에서 양옆 빈 곳의 터치
  스크롤(합성 터치는 칸 가운데에서도 스크롤하지 않아 이 환경에서 확인하지 못함)은 §12의 몫이다.
- Linux에서는 새 명세를 돌리지 않았다(머지 뒤 Full E2E가 첫 Linux 실행). 4px 여유 계산은 같은 글꼴 파일로 잰 것이라 iOS Safari와 Linux에서 그려진
  폭은 다를 수 있고(전부터 있던 한계, release-record §2 9.0.21 절), 안전 영역 여백은 계산하지 않는다.
- 숨은 역할 고르기 칸과 링크로 들어오는 참여 단계(`#setup-auto-join-area`, 찍은 단계와 같은 구조)는 찍지 않았다. 방 만들기 단계는 WebKit에서 방 번호가
  20초 안에 나오지 않아 WebKit 사진이 없다.
- 9.0.36 보고서 §11 7의 주석 셋(release-record §2 9.0.36 절의 다음 단계 (3))은 이 열차에도 없다. App 런타임 경로라 넣으면 버전 올리기를 다시 두어야
  하므로 다음 앱 열차에 넣을지는 릴리스 담당이 정한다(빌드 결과는 바뀌지 않음).
- `src/ui/dom.ts`와 겹치는 숨은 textarea 복사 함수를 한 모듈로 모으는 일은 뒤 일이다.
