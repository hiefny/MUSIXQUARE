## 1. 끌기 중 핸들과 재생 상태 아이콘 겹침

- 원인: 끌 때 떠 있는 복제본(`makeGhost`)이 현재 곡 행의 `playlist-current-leading is-current-*` 클래스와 재생/정지/로딩
  아이콘을 그대로 복제했다. 상태 아이콘을 보이게 하는 규칙(특이도 0,3,0)이 복제본에서 숨기는 규칙(0,2,0)을 이겨, 같은
  격자 칸의 ≡ 그립과 아이콘이 함께 보였다. 원래 행은 문제없었다.
- 변경: 복제본에서 상태 아이콘과 상태 클래스를 지운다(`src/ui/playlist-reorder.ts`). 복제본에는 그립만 보인다.

## 2. 컴퓨터에서 길게 클릭해 순서 바꾸기

- 마우스·펜 주 버튼을 행 아무 곳(제목 버튼 포함, 삭제 X 등 다른 컨트롤 제외)에 700 ms 누르고 있으면 터치 길게
  누르기와 같은 끌기가 시작된다. 짧은 클릭은 지금처럼 재생된다. 8 px 이상 움직임, 손 뗌, 목록 밖으로 나감, 스크롤,
  다른 버튼, 컨텍스트 메뉴, Escape면 취소된다. 포인터 캡처는 끌기가 시작될 때만 잡아 짧은 클릭을 바꾸지 않는다.
  끌기 뒤 클릭은 기존 억제 장치가 삼킨다. 권한·삭제 선택 중 차단은 그대로다.

## 3. 아이폰에서 길게 누르면 글자가 선택됨

- 원인: 소스 CSS는 그대로였다. 8.6.9(2026-09-09, Vite 8 업그레이드)부터 CSS를 lightningcss가 Chromium 79 하나만
  대상으로 압축하면서 iOS Safari가 읽는 유일한 형태인 `-webkit-user-select: none`을 모두 지웠다(빌드 결과 8개 중 0개).
  8.4.28에 CSS 대상을 `chrome79`로 바꾼 것은 Vite 7 esbuild에서는 접두사를 지우지 않아 드러나지 않았다. 윈도우·안드로이드
  Chromium은 접두사 없는 `user-select`를 읽어 영향이 없었다.
- 변경: CSS 대상에 Safari 15·iOS 15를 더했다(`scripts/browser-target.ts`의 `APP_CSS_BROWSER_TARGETS`). JavaScript 대상은
  webOS 때문에 Chromium 79 그대로다. 빌드 가드(`guard:legacy-tv-build`의 `assertTouchSelectionCss`)가 빌드 CSS에
  `-webkit-user-select: none`이 없으면 실패한다. 빌드 결과 접두사 규칙 7개, CSS 크기 약 0.9 KB 증가, Chromium 79 정적
  검사 통과.

## 4. 컴퓨터에서 끌 때 계속 스크롤됨

- 재현된 원인: 데스크톱 재생목록 칸은 짧은데(1280×720에서 245 px) 가장자리 자동 스크롤 영역이 높이의 16%, 최소 40 px로
  한 행(64 px 간격)에 가까웠다. 스크롤 루프가 끌기 시작부터 놓을 때까지 돌아, 가장자리 행을 잡기만 해도 스스로
  스크롤했다(고치기 전 0.8초에 약 180 px).
- 변경: 영역을 칸 높이의 12%, 24~72 px로 줄이고, 끌기 시작 위치에서 가장자리 쪽으로 8 px 이상 움직였거나 영역 밖에
  있었던 뒤에만 그 가장자리가 동작한다. 루프는 영역 안에 있는 동안만 돌고 영역을 벗어난 첫 프레임에 멈춘다. 끌기 중
  휠 스크롤도 놓일 자리를 갱신한다.
- 한계: "가운데로 돌아와도 계속 스크롤" 그대로의 증상은 headless Chromium에서 재현하지 못했다. 위 두 원인을 고쳤고
  루프 정지 조건을 새로 만들었다.

## 5·7·8·9. 백그라운드 복귀 동기화와 삭제 모드

각각 별도 보고서에 적었다. 삭제 모드는 그 뒤 오너 지시로 다음을 더 바꿨다.

- 실행 취소 제거(오너 결정 2026-10-21): 삭제는 X로 고르고 삭제를 누르는 두 단계라 이미 충분하고, 3초 실행 취소 창은
  PRO 방에서 사고 위험이 있다. 그래서 실행 취소 pill과 대기 상태, 그리고 그 대기 때문에 넣었던 재생 이동 전 확정
  장치(`0e00c0e0`: `queue-removal-gate`, PRO 이동 대기, 곡 끝 3초 전 확정)를 모두 없앴다. 삭제를 누르면 바로
  `playlist:remove-tracks`를 보낸다. 대신 삭제한 기기에만 "트랙 N개를 삭제했어요"(`toast.deleted_tracks`) 토스트를 띄운다.
  방송하지 않으며, 재생목록에서 실제로 사라졌을 때(방장은 즉시, PRO·게스트는 방의 최신 목록이 왔을 때) 띄워 거절되거나
  응답이 없는 요청은 성공처럼 보이지 않는다. `common.undo` 키는 42개 언어에서 지웠다.
- 삭제/취소 pill은 하나의 큰 컨테이너 pill(`--surface-1`, 안쪽 6 px, 라이트 대화상자 회색 버튼과 같은
  `1px solid var(--glass-border)` 테두리, 그림자 없음) 안에 들어 있다. 컨테이너는 마지막 곡 바로 아래 16 px에 붙고,
  목록이 화면보다 길면 화면 아래(휴대폰은 하단 내비게이션 14 px 위)에 떠 있다(sticky). 끝까지 스크롤하면 다시 마지막
  곡 아래로 돌아와 곡을 가리지 않는다.
- 삭제 모드가 끝나면(삭제, 취소, 모두 선택 해제, 바깥 누르기, 탭 이동) 컨테이너 전체가 한 덩어리로 조금 내려가며
  사라진다(300 ms, 동작 줄이기 설정에서는 즉시). 그 사이 다시 고르면 퇴장을 멈추고 다시 나타난다.
- 삭제 버튼은 빨간색(`--danger-filled`)이다. 삭제하면 남은 곡이 300 ms로 부드럽게 제자리로 이동한다.
- 오른쪽 버튼은 "Select all (전체 곡 수)"이고, 모두 선택됐을 때는 숫자 없는 "Deselect all"이다. 왼쪽 제목과 글자 기준선을
  맞췄다. 색은 파란색 대신 왼쪽 제목과 같은 `--text-main`이다(오너 결정 2026-10-21).
- 한국어 삭제 버튼은 오너 문구 "삭제하기"를 쓴다.
- 재생 이동 전 확정 장치를 없애 초기 JavaScript 예산 여유가 58 B에서 971 B로 늘었다(490,597 / 491,568 B gzip).

## 6. 블로그 사진 전부 깨짐

- 증상: 블로그 목록·글의 모든 사진이 `/soro-images/featured/<slug>.<version>.webp`에서 404였다. 원본(Supabase) 주소는
  200이고 R2 바인딩도 있다. 2026-09-06(#149)부터 사진 주소가 버전 이름을 쓰는데, 그 이름의 R2 객체가 없다(R2 버킷
  객체 55개는 이전 이름). 요청 때 원본을 받아 저장하는 단계가 운영 환경에서 실패한다. Worker가 로그를 남기지 않아
  어느 단계에서 실패하는지는 밖에서 확인하지 못했다.
- 변경: 저장에 실패하면 404 대신 허용 목록의 원본 주소로 302를 보내고(CSP가 이미 허용), 저장 상태를
  `X-Soro-Image-Mirror` 헤더에 남긴다. 배포 뒤 이 헤더로 실제 실패 단계를 읽는다.

## 10. 권한 확인 중 안내 (추가 요청)

- 권한이 아직 확인되지 않았을 때만 "<권한>을 확인 중이에요\n잠시 후 다시 시도해 주세요"를, 확인됐는데 없으면 기존
  "<권한>이 없어요" 안내를 보인다. 실제 허용 판단(`hasRoomCapability`)은 바뀌지 않았다.
- 확인 중의 정의: 일반방 게스트가 지금 연결에서 방장의 권한 알림(OPERATOR_GRANT/REVOKE)을 아직 받지 못했을 때, 그리고
  입장 중이거나 재연결을 기다릴 때. 방장은 연결이 맺어지면 일반 게스트에게도 이 알림을 보낸다. 재연결은 새 연결이라
  다시 확인 중이 된다. PRO 방은 권한이 방 정보와 함께 오므로 확인 중이 없다.
- 한계: PRO 방에서 로그인·로그아웃을 처리하는 짧은 순간에는 권한이 비워져 "확인 중" 대신 "없어요"가 나온다.
- 새 키 6개 × 42개 언어. 각 언어의 기존 권한 명사와 "잠시 후 다시 시도" 문구를 재사용했다. 한국어는 오너 문구다.

## 화면 높이별 데스크톱 레이아웃 (추가 요청)

가로 1280 px 이상에서 높이 720 px 미만은 태블릿 화면, 720~899 px는 헤더가 재생 칸 위에만 있고 오른쪽 칸이 전체 높이를
쓰는 데스크톱, 900 px 이상은 기존 데스크톱이다(오너가 처음 540/720 px로 정했다가 720/900 px로 바꿨다). CSS와 JS가
`src/core/layout-breakpoints.ts`의 같은 문자열을 쓰고 계약 테스트가 지킨다.
