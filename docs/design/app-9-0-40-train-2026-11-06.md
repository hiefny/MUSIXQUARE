## 1. 오너 결정

오너의 말은 옮기지 않고 뜻만 적는다.

- **2026-11-06, 공개 페이지의 한국어 큰 제목 자간:** 공개 페이지에서 한국어 큰 제목의 자간을 앱처럼 0으로 한다. 앱은 9.0.29부터 음수 자간이
  없다: 라틴은 Inter의 광학 크기 축이 스스로 좁히고, 한글은 그런 축이 없는 Pretendard 기반의 'MUSIXQUARE Hangul' 면이라 앱에서 한국어는 어디서도
  좁혀지지 않는다. 공개 페이지는 지금도 모든 언어의 큰 제목을 좁히고, 한국어도 함께 좁혀졌다. 공개 페이지는 사진 확인 없이 앱의 체계를 따르고
  앱만 오너가 확인한다는 상시 규칙대로 사진 없이 적용한다.
- **같은 날, 범위(릴리스 담당이 정함):** 공개 페이지에서 그려진 글자에 한글이 든 요소는 크기와 상관없이 음수 대신 자간 0이다(앱에는 한국어 음수
  자간이 어디에도 없음). 규칙은 한국어 글자에 맞춘다: 보통은 각 시트의 이미 있는 `:lang(ko)` 규칙 옆에 `:lang(ko)` 규칙을 두어, 한국어 페이지만
  바뀌고 다른 모든 언어는 오늘과 같다. 한글이 들지 않는 요소(숫자뿐인 시각과 통계 값, 라틴 브랜드 낱말, 코드)는 모든 언어에서 자간을 지켜, 같은
  숫자가 한국어와 영어 페이지에서 같아 보인다(오너는 2026-10에 같은 내용이 언어마다 다른 자간으로 그려지는 것을 싫어했다). 광학 왼쪽
  여백(`margin-left: -0.03em`)과 양수 자간(작은 대문자 라벨, 코드)은 그대로이고, 일본어, 중국어와 그 밖의 언어, 앱(`css/style.css`, `src/`), OG
  이미지 생성기는 건드리지 않는다.

## 3. (1) 공개 페이지의 한국어 자간 0 [화면 바뀜]

공개 페이지 가운데 한국어로 그려지는 것은 소개(`/ko/about.html`과 한국어 브라우저의 `/about.html`), 이벤트 페이지(늘 `lang="ko"`), 로그인 완료

요소는 소개의 큰 제목 셋과 채팅 말풍선, 이벤트 페이지의 제목들뿐이었다(측정은 §3.5).

### 3.1 의도한 변경 (페이지와 규칙마다)

- **소개, `public/editorial-base.css`:** 이미 있는 `:lang(ko) .lp-h1`(첫 제목, 다른 언어는 −0.03em), `:lang(ko) .lp-h2`(절 제목, −0.035em),
  `:lang(ko) .lp-cta .lp-h2`(마지막 제목, `public/editorial-about.css`의 −0.03em)에 `letter-spacing: 0`을 더했다. 첫 제목의 광학 왼쪽 여백
  `margin-left: -0.03em`, 그 규칙들의 크기와 줄 높이는 그대로다.
- **소개, `public/editorial-about.css`:** 새 규칙 `:lang(ko) .lp-chat-bubble:not(.lp-chat-bubble--yt) { letter-spacing: 0 }`이 한국어 채팅 말풍선
  글자(−0.01em)를 0으로 한다. YouTube 말풍선은 모든 언어에서 같은 라틴 제목만 담아 빠진다. 말풍선 안의 재생 시각 `.lp-chat-ts`는 이제 스스로
  `letter-spacing: -0.01em`을 선언한다: 말풍선과 같은 14px이라 모든 언어에서 지금과 같게 그려지고, 한국어 말풍선이 0이 되어도 시각 숫자는 영어
  페이지와 같은 −0.14px다.
- **이벤트, `public/events/event.css`:** 공유 제목 규칙(`.stage-copy h1`, `.success-guide h2`, `.nickname-form h2`)의 −0.035em을 0으로 했다. 이
  페이지는 언어 전환이 없고 늘 `lang="ko"`라(영어 브라우저에서도, 측정함) `:lang(ko)` 사본 대신 공유 규칙을 고쳤다. 그리는 결과는 같고, 한 언어만의
  페이지에 한 언어 규칙을 글꼴 가드에 등록하지 않아도 된다(§3.3).
- **가드:** `scripts/check-app-font.mts`의 공개 페이지 검사가 `:lang(ko) …` 사본 규칙의 `letter-spacing: 0`만 받아들인다(§3.3).
  `scripts/lib/public-font-pages.mts`의 `PUBLIC_KOREAN_ENGLISH_COPY_RULES`는 주석과 이유를 고치고 말풍선 선택자를 더했다.

### 3.2 그대로 두는 것

- 다른 모든 언어(일본어, 중국어 포함)의 공개 페이지는 픽셀까지 같다(§3.5). 일본어 `.lp-h1`의 `:lang(ja)` 0은 전부터 있던 것이다.
- 한글이 들지 않는 요소는 한국어 페이지에서도 자간이 같다: 소개의 재생 시각(`.lp-sync__timecode`, `.lp-sync__peer-tc`), 채팅 시각 `.lp-chat-ts`
  (모두 숫자), YouTube 말풍선의 라벨과 제목(`.lp-chat-yt__label`, `.lp-chat-yt__title`), 라틴 브랜드 낱말, 코드. 그래서 같은 숫자가 한국어와 영어
  페이지에서 같은 글자 크기와 같은 음수 자간으로 그려진다.
- 양수 자간(작은 대문자 라벨, 코드)과 광학 왼쪽 여백은 그대로다.
- 앱(`src/`, 이 부분은 `css/style.css`도 건드리지 않음), OG 이미지 생성기, 서비스 점검 페이지(`cloudflare/service-maintenance.ts`)는 바뀌지 않는다.
  점검 페이지는 고칠 것이 없다: 그 −0.04em `.headline`은 모든 언어에서 `<h1 lang="en">` 안의 영어 문장 'MUSIXQUARE is temporarily unavailable.'이고,
  한국어 설명 `<p>`는 이미 0(normal)이다(독립 리뷰가 `maintenanceHtml('ko')`와 `('en')`을 그려 잼). 한글이 든 글자가 거기서 좁혀지지 않으므로 이
  범위에서 빚진 것이 없고, 모든 Worker를 내는 다음 릴리스로 미룰 일도 없다.
- 공개되지 않는 내부 페이지(`.workshop`의 비공개 페이지, `e2e/report-viewer.html`, ui-kit의 정적 범례)는 건드리지 않았다. 공개로 나가는
  사이트맵의 음수 자간 제목은 영어뿐이라 그대로다(측정함).

### 3.3 글꼴 가드 계약이 좁게 풀림, 이벤트 페이지의 공유 규칙

- 9.0.36(공개 페이지 글꼴 열차)은 한 언어에만 걸리는 규칙이 자간을 정하지 못하게 했다(그때 소개의 한국어만 −0.025em을 뺐고, 가드와 단위
  시험이 그것을 지켰다, [공개 페이지 글꼴 보고서 §2.2](public-page-fonts-2026-11-02.md#22-페이지마다-거는-방법)와 Q3). 한국어에 맞춘 범위대로 그
  계약을 좁게 풀었다: `:lang(ko) …` 사본 규칙은 이제 `letter-spacing`을 정확히 `0`으로만 정할 수 있고, 그 밖의 한 언어 자간은 여전히 실패한다.
  `:lang(ko) .lp-h1`을 −0.01em으로 바꾸면 글꼴 가드와 정적 시험이 둘 다 실패하는 것을 봤다(만든 단계와 독립 리뷰). 2026-11-02 보고서는 그때의
  기록으로 두고 고치지 않는다.
- **리뷰 뒤 고정(`8471495c`, 시험만, 라운드 4):** 글꼴 가드는 등록된 `:lang(ko)` 사본 규칙이면 바탕 값과 상관없이 0을 받아들인다. 그래서 뒤에
  등록된 한국어 사본이 양수 자간(작은 대문자 라벨, 코드)을 0으로 만들어도 가드는 지나갈 수 있었고, 정적 시험은 음수 선언만 적었다(오늘 이
  갈래에 그런 규칙은 없음, 두 번째 독립 리뷰가 확인). 정적 시험에 시험 하나를 더해, `:lang(ko)` 선택자가 든 규칙의 자간은 0이고 그 선택자는
  모두 목록(`KOREAN_AT_ZERO`)에 적힌 음수 자간의 사본이어야 하며 그 선택자 모음이 목록의 사본과 같아야 하게 했다. 오늘은 통과하고,
  `public/editorial-base.css`에 `:lang(ko) .lp-btn { letter-spacing: 0 }`(0.01em 버튼 라벨)을 더하면 그 시험이 실패한다(그 규칙은 등록되지 않은
  사본이라 글꼴 가드도 실패).
- 이벤트 페이지의 공유 제목 규칙은 이제 모든 언어에서 0이다. 지금 그 페이지는 늘 한국어라 다른 언어는 바뀌지 않는다. 다만 글꼴 등록부
  (`PUBLIC_FONT_PAGES`)의 이벤트 항목은 `htmlLangs`를 `['ko', 'en']`으로 적고 있어, 언젠가 영어 이벤트 페이지가 생기면 그 제목은 다른 공개 영어
  제목과 달리 0으로 그려진다. 그때 `htmlLangs`를 `['ko']`로 좁히거나 `:lang(ko)` 사본으로 바꾼다(지금은 막지 않음).

    힌디어 4 ~ 8프레임(모음 표시 u와 uu의 아래 끝, 기기 배율 2에서 아래 4, 3, 2, 2, 1줄, 기기 배율 1에서 5프레임 많아야 2줄), 베트남어
    4프레임(a 아래 점의 아래 2줄), 아랍어 4프레임(ya 아래 점의 아래 2줄, 5 ~ 7프레임에 아주 작은 자취)의 가장 아래 표시를 잠깐 자른다. 타이어는
    9.0.39도 4프레임부터 모든 프레임과 다 열린 알약에서 성조 표시를 2줄 자르고, 새 빌드는 기기 배율 2의 4 ~ 6프레임에 2줄 대신 3줄이라 거의 같다

    말라얄람어는 세 빌드 모두 두 배율에서 0이다.
  - **보이는 정도:** 1배 그림에서는 눈으로 9.0.39와 같다. 2배를 4배로 키운 멈춘 프레임에서는 잘린 끝이 보이지만, 움직일 때는 라벨이 아직
    펼쳐지며 크기와 굵기가 바뀌는 1 ~ 5프레임(17 ~ 83 ms)뿐이라 보이지 않는다고 판단했다(검증도 배포를 막지 않는다고 봄). 그래서 리뷰가 낸 고침을
    그대로 썼다.

## 5. 바뀌지 않는 것

- **공개 페이지:** 한국어가 아닌 모든 언어의 공개 페이지는 네 폭에서 픽셀까지 같다(§3.5). 한국어 페이지에서도 한글이 들지 않는 요소(숫자뿐인
  시각과 통계 값, 라틴 브랜드 낱말, YouTube 말풍선의 라틴 제목, 코드), 양수 자간, 광학 왼쪽 여백, 글자 크기와 줄 높이, 면은 그대로다. 로그인
  완료 창은 네 폭 모두 같다. 서비스 점검 페이지는 고칠 것이 없다(§3.2).

  넘겨받은 번호가 첫 프레임부터 보이는 것(9.0.39의 넘겨주기).
- **그 밖:** 앱의 다른 화면(`src/`는 바뀌지 않음), OG 이미지 생성기, 방 안 통신, 저장, 서버, 42개 언어의 문구(문자열 변경 없음), 서비스 워커

## 14. 하지 않은 것과 확인하지 않은 것

- 라운드 1 ~ 4와 최종 독립 검증에서는 push, PR, PR CI, 자동 코드 리뷰, exact-main CI, 배포, 운영 확인, 머지 뒤 Full E2E를 하지 않았다(릴리스
  단계 몫, 그 결과는 §13.7). 오너의 기기 확인(§9 (A), (B))은 배포 뒤에도 아직이다.
- 단위 전체에서 부하로 30초 한도를 넘는 git 고정물 행(`release-deployment-state`, 이 열차가 바꾸지 않음)은 혼자 돌려 통과했을 뿐 고치지
  않았다(§13.4). 라운드 4의 단위 전체에서는 그 행도 통과했다.
- 실기기(iPhone Safari·iPad, Android, 여러 데스크톱 브라우저)는 두 부분 모두 없다. 공개 페이지의 측정과 픽셀 비교는 Chromium 153뿐이고, Worker가
  그리는 블로그 글과 관리자 페이지는 정적으로만 봤다(둘 다 이미 0이거나 영어뿐). 운영에서는 데스크톱 Chromium에서 한국어·영어 소개의 제목 셋과
  숫자뿐인 시각만 쟀다(§13.7).
- 공개 페이지의 정적 목록은 시트와 `<style>`의 글자 그대로의 음수 값만 본다(`var()`로 오는 값과 `style` 속성은 못 봄). E2E는 글자 노드, placeholder,
  value를 보고 `::before`·`::after`의 글자는 보지 않는다. 오늘은 한글을 담은 가상 요소도, `var()`나 인라인 음수 자간도 없다(측정함).
- 이벤트 페이지의 다른 단계와 닉네임 창은 실제 API 데이터 대신 DOM으로 보이게 해서 쟀다. 픽셀 비교는 동작 줄이기의 마지막 모습이고 움직이는 중의
  모습은 아니다.
- 데모 단계 라벨: WebKit의 여는 프레임과 기기는 보지 않았다(9.0.39의 넘겨주기와 같은 한계). 오른쪽에서 왼쪽으로 쓰는 언어는 Chromium의 아랍어
  390 하나만 봤다(라운드 4, 누르는 프레임이 점과 같음). 이 PC의 WebKit에서는 데모 명세가 방을 만들지 못해 데모에 닿지 않는다(§13.4). 알약 선택
  굵기 규칙의 `.is-collapsing` 쪽은 이제 단계 버튼에서 하는 일이 없지만 계약 셋이 고정해 두었다(주석은 라운드 4에서 고침, 규칙은 뒤에 정리할 수
  있음).
- 소개 채팅의 한 문구(`remote.peer_ts_msg`, 한국어와 영어)는 '트랙' 대신 다른 낱말을 쓴다. 이 열차는 그 자간만 바꾸고 문구는 바꾸지 않았다(문구는
  오너 결정 밖).
