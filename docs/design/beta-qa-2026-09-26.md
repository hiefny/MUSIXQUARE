# Beta QA — 2026-09-26

Baseline: `mxqr_beta` at `301e60bc`. Scope: hybrid local-file playback,
ordinary/PRO synchronization, demo/session transitions, and their UI projections.
This work stays on beta; it does not advance `main`, change the release/cache
version, deploy production, or enable Operations Drift Audit.

## Confirmed findings

1. **Stopped decoder readers could overlap successor seeks.** The previous gate
   retired cancelled preparation readers but did not include stopped playback.
   A controlled pending read reproduced opening position 90 while position 0 was
   still retiring. Every actual reader opening now observes retirement, including
   clock-advanced cold starts and background catch-up. Cancellation interrupts
   waiting openings; still-active playback can continue during replacement
   preparation. This orders application reader lifetime, not synchronous
   destruction of every backend Worker.
2. **A bounded decoder could repeatedly retry a failed segment.** Failures after
   initial priming bypassed the existing unavailable-track policy. A real
   authenticated ordinary-room `SYNC_PONG` reproduced a second prepare after
   terminal failure. Playback, later seek, and synchronous first-PCM failures now
   retire the failed resource and reuse the existing guest/PRO unavailable-track
   or standard-host advancement policy. Decoder startup and native output-device
   failures remain retryable. A failed manual-sync replacement preserves a
   healthy existing output.
3. **An obsolete manual-sync request could reopen a dismissed panel.** Deferred
   PRO completion checked room ID without its incarnation; ordinary YouTube
   completion also ignored dismissal. Requests now validate their generation,
   room epoch, connection, media mode, and queue item. Explicit dismissal cancels
   them; temporary hiding while a valid PRO reconciliation replaces its resource
   does not cancel the request.
4. **Interrupted demo exit could overwrite a new room's effects.** Disconnecting
   during demo, then joining another room during the exit animation, restored
   the old audio snapshot over the new room's reverb/EQ. Interrupted restoration
   now retains the exit context's identity. Normal demo exit still preserves the
   user's effect changes; interrupted recovery in the same context still restores
   its prior settings.
5. **Paused late join could show zero while retaining the correct position.** Real
   Chromium host/guest tests reproduced `player.pausedAt=240` with a displayed
   seek value of zero after duration publication. This occurred in both mixed
   engine directions and with both participants bounded. The paused timeline
   now refreshes when its authoritative position or duration changes. Playing
   interpolation, pending PRO seeks, and active user drafts keep their ownership.

Each finding has focused regression coverage. New browser cases cover paused
late join, repeated near-end/backward seeks, resume, and return to a small native
track with bounded/bounded and both native/bounded participant combinations.

Browser inspection confirmed correct paused state and no unintended audio
starts; the defect was the displayed position.

## Limits

Browser checks use real local Chromium contexts and local signaling. PRO
authority/failure and deferred UI cases use production code with controlled unit
fixtures. They do not establish live Cloudflare behavior, physical speaker
alignment, real iPhone Safari/PWA behavior, or every possible long-session order.
No claim of exhaustive QA or a production release is made.
