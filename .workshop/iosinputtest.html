📱 iOS IME Chat Input Test

재현 방법:
  1. 각 variant의 입력창 탭 → 한국어 키보드 전환
  2. 안녕하세요 타이핑 → Send 누르거나 Enter
  3. 바로 다시 안녕하세요 타이핑 시도
  4. 첫 글자가 요로 시작하면 = 누수 발생 🐛

태그: FOCUS-RISK 전송 후 포커스 깨질 수 있음 · FLASH 키보드 1프레임 깜빡

1. Baseline (현재 프로덕션)

contentEditable 값 토글 'false' → '' → 'true', synchronous focus().

2. + synthetic compositionend

전송 직전 CompositionEvent('compositionend', { data: '' }) dispatch 추가.

3. + selection.removeAllRanges()

clear 이후 selection range 제거. FOCUS-RISK

4. removeAttribute('contenteditable') + rAF focus

속성 자체 제거 후 재추가, 다음 프레임에서 focus. FOCUS-RISK

5. blur + rAF + refocus (하드 리셋)

blur로 IME 세션 완전 종료 후 rAF로 refocus. FLASH

6. blur + immediate focus (동기)

blur 직후 같은 tick에서 focus. 키보드 안 닫힐 수도. FLASH

7. 지연 clear (setTimeout 50ms)

즉시 clear 후 50ms 뒤 2차 clear — iOS가 flush하고 난 뒤 누수분 제거.

8. 즉시 clear + 다음 rAF clear

innerHTML 2번 clear — 두번째는 다음 rAF에서 (누수 캐치).

9. beforeinput 감지 기반 (변경: 다음 입력에서 처리)

clear는 기본 토글, 추가로 beforeinput에서 직전 전송의 마지막 문자가 새 입력 앞에 붙어있으면 제거.

10. 합: compositionend + removeAttr + blur + rAF focus

모든 전략 합친 풀 누크. 포커스 깨지거나 키보드 깜빡할 수 있음. FOCUS-RISK FLASH

11. removeAllRanges + 빈 Range 재추가 ⭐ 유력

Variant 3의 누수 차단 효과 유지 + caret을 input 시작 지점에 재설정해서 포커스 유지.

12. Selection.collapse(input, 0) — 모던 API

removeAllRanges 대신 selection을 input 시작점으로 collapse. caret 유지.

13. selectNodeContents + collapse(true)

range.selectNodeContents(input) + range.collapse(true) — input 내용 전체를 선택했다가 시작점으로 접음.

14. removeAllRanges + 빈 Range 재추가 (contentEditable 토글 없이)

11번과 동일하지만 contentEditable 'false'→'true' 토글 생략. innerHTML만 clear + selection 리셋.

15. Dummy input 포커스 스왑 (동기) ⭐ 유력

transient한 <input type="text">에 focus → 원본 clear → 원본에 focus 복귀. 동기 실행.

16. Dummy input 스왑 + rAF 복귀

dummy focus → clear → 다음 프레임에 원본 focus. 이벤트 루프 한 tick 여유.

17. Dummy input 스왑 + microtask 복귀

dummy focus → clear → queueMicrotask로 복귀. rAF보다 빠름.

18. Dummy textarea 스왑 (sync)

textarea는 contenteditable과 다른 IME 세션 타입 — swap 효과가 더 깊을 수도.
