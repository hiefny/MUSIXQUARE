# 화면 높이에 따른 데스크톱 레이아웃 (2026-10-21)

> 2026-10-21 오너 재지정: 높이 기준을 540/720px에서 **720/900px**로 옮겼다. 아래 표와 쿼리는 새 값이고, "측정" 절의 숫자는 처음 540/720px 기준 커밋 `ded548c4`에서 잰 값이다. 새 기준의 화면 확인은 [묶음 보고서](playlist-and-platform-fixes-2026-10-20.md)에 있다.

- Status: 미배포 UI 변경·검증 기록이다. 제품 버전과 서비스 워커 캐시는 올리지 않았다. 배포하면 결과의 정본은
  [릴리스 기록](../release-record.md)과 [릴리스 이력](../release-history.md)이다.
- 계기: 오너 요청(2026-10-21). 폭 1280px 이상이면 높이와 관계없이 세 칸 대시보드(재생 | 재생목록·채팅 | 설정,
  위에 전체 폭 머리글)를 썼다. 높이가 낮은 넓은 창에서는 머리글 60px가 세 칸 모두의 높이를 깎았다.
- 커밋: `ded548c4`(레이아웃·공유 기준·테스트).

## 기준

| 화면                        | 레이아웃                                   |
| --------------------------- | ------------------------------------------ |
| 폭 < 720px                  | 휴대폰 (변화 없음)                         |
| 폭 720–1279px               | 태블릿 사이드바 (변화 없음)                |
| 폭 ≥ 1280px, 높이 < 720px   | 태블릿 사이드바 (새로 강제)                |
| 폭 ≥ 1280px, 높이 720–899px | 세 칸 대시보드, 머리글은 재생 칸 위에만    |
| 폭 ≥ 1280px, 높이 ≥ 900px   | 세 칸 대시보드, 전체 폭 머리글 (변화 없음) |

기준은 `src/core/layout-breakpoints.ts` 한 곳에 있다.

- 데스크톱: `(min-width: 1280px) and (min-height: 720px)`
- 데스크톱 아님: `(max-width: 1279px), (max-height: 539px)`
- 태블릿 사이드바: `(min-width: 720px) and (max-width: 1279px), (min-width: 1280px) and (max-height: 719px)`
- 낮은 데스크톱: `(min-width: 1280px) and (min-height: 720px) and (max-height: 899px)`

미디어 쿼리는 배율을 적용하기 전의 레이아웃 뷰포트(CSS px)를 잰다. 데스크톱 밀도 배율(1.2/1.5,
`--desktop-ui-scale`)은 높이 1280px·1900px 이상에서만 켜지므로 720·900 경계와 겹치지 않는다. 그래서 CSS와
JS(matchMedia)가 같은 문자열로 같은 결과를 낸다.

## 변경

- CSS: 기존 `(min-width: 1280px)`·`(max-width: 1279px)`·태블릿 쿼리를 위 문자열로 바꿨다(`style.css`,
  `desktop.css`, `playback-actions.css`). 태블릿 쪽 규칙은 이미 폭 720px 이상 기준이라 높이로 강제한 태블릿에도
  그대로 맞는다. 세로 방향 전용 쿼리 2개는 폭 1280px 이상이면서 높이 720px 미만인 세로 화면이 없으므로 그대로 뒀다.
- 낮은 데스크톱(`desktop.css` 끝의 새 블록): 머리글을 재생 칸에만 두고(`grid-template-areas` 첫 줄
  `'header tab-playlist tab-settings'`), 재생목록과 설정은 화면 맨 위부터 아래 끝까지 쓴다. 재생목록·채팅은 지금처럼
  반반이다(첫 두 행 합이 50%). 머리글 오른쪽 끝에 칸 구분선을 이어 그렸다. 재생목록·설정 칸은 위쪽 안전 영역만큼
  스스로 띄우고, 제목 줄 위 여백을 32px에서 12px로 줄여 제목이 머리글의 60px 줄 가운데(로고와 같은 높이)에 온다.
- JS: 채팅 서랍(데스크톱 여부·반 높이 판정), 사용자 스크롤바, 재생목록 항상 보임·순서 바꾸기, 시작 화면 왼쪽 패널과
  등장 동작, 탭 전환 시 데스크톱 패널 새로고침, 데모 화면 전환이 모두 공유 상수를 쓴다. 사용자 스크롤바는 낮은
  데스크톱 경계를 넘을 때도 다시 배치한다(옆 칸 위치가 바뀌므로).
- 데모 화면(`demo/mode.ts`)은 "데스크톱 아님" 쿼리로 바뀌어, 높이로 강제한 태블릿에서도 태블릿처럼 다시 그린다.

## 검증

- e2e 빌드(`ded548c4`), Playwright Chromium, 방을 만들고 트랙 3개를 올린 뒤 잰 값(다크·라이트 동일, 단위 px,
  x, y, 폭, 높이). 모든 크기에서 문서 가로 스크롤 없음, 머리글·각 칸이 화면 밖으로 나가지 않음.

  | 화면     | 머리글                     | 재생            | 재생목록          | 채팅               | 설정               |
  | -------- | -------------------------- | --------------- | ----------------- | ------------------ | ------------------ |
  | 1440×500 | 사이드바 1240, 0, 200, 500 | 0, 0, 1240, 500 | 탭 숨김           | 서랍 닫힘          | 탭 숨김            |
  | 1440×620 | 0, 0, 600, 60              | 0, 60, 600, 560 | 600, 0, 420, 310  | 600, 310, 420, 310 | 1020, 0, 420, 620  |
  | 1280×560 | 0, 0, 440, 60              | 0, 60, 440, 500 | 440, 0, 420, 280  | 440, 280, 420, 280 | 860, 0, 420, 560   |
  | 1440×900 | 0, 0, 1440, 60             | 0, 60, 600, 840 | 600, 60, 420, 420 | 600, 480, 420, 420 | 1020, 60, 420, 840 |
  | 1024×700 | 사이드바 824, 0, 200, 700  | 0, 0, 824, 700  | 탭 숨김           | 서랍 닫힘          | 탭 숨김            |

  1440×900과 1024×700은 이 범위의 규칙이 쿼리 문자열만 바뀌어 배치가 그대로다(main 빌드에서 따로 재지는
  않았다). 낮은 데스크톱에서 재생목록·설정 제목은 y 12–48(가운데 30),
  로고는 y 22–38(가운데 30)이다.

- 실행 중 크기 바꾸기: 1440×900 → 1440×620 → 1280×560 → 1440×500 → 재생목록 탭 → 1440×620 → 1440×900에서 매번
  새로 연 것과 같은 배치가 됐다. 1440×500에서 채팅 서랍은 전체 높이(반 높이는 300px 미만이라 원래대로 막힘)로
  열리고 배경을 `inert`로 막는다. 그 상태에서 1440×620으로 넓히면 채팅이 대시보드 칸으로 돌아가고 `inert`가 풀린다.
  1440×620에서 미디어 선택 창은 재생 칸 안에, 계정 창은 화면 가운데에 뜬다. 시작 화면은 1440×620에서 데스크톱
  두 칸, 1440×500에서 태블릿 두 칸이다.
- 새 e2e `e2e/desktop-height-layout.test.ts`(2개): 위 기준 9가지 크기를 차례로 바꾸며 머리글·칸 경계, 반반 분할,

## 한계

- 실기기는 보지 않았다. 특히 폭 1280px 이상 태블릿의 위쪽 안전 영역(설치 앱)은 코드로만 맞췄다.
- 높이 기준이 생겨, 키보드가 레이아웃 뷰포트를 줄이는 브라우저(예: Chrome 108 이전 Android)에서는 넓은 태블릿에서
  입력 중 레이아웃이 바뀔 수 있다. 지금 Chrome·Safari는 키보드가 시각 뷰포트만 줄여 해당하지 않는다.
- 1280×560처럼 재생 칸이 낮으면 재생 칸 내용이 칸 안에서 스크롤된다. 재생 칸 크기는 바꾸기 전과 같아 이번 변경
  범위 밖이다.
- 스크린샷은 저장소 밖 로컬 임시 폴더에만 두었다(커밋하지 않음). WebKit과 QHD·4K 배율 화면은 이번에 재지 않았다.
