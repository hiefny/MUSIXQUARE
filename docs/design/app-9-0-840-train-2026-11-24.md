## 1. 오너 결정

오너의 말은 옮기지 않고 뜻만 적는다.

- 2026-11-24 UI 검토 과정에서 목록 행 아이콘의 크기 근거와 호버 동작을 점검했다.
- 서브기기 행(`.device-subrow`, `min-height: 44px`, `padding: 8px 12px` → 안쪽 여유 `28px`) 때문에 강퇴·권한 해제 X 버튼이 `28px`를 쓰는 근거는 유지하고,
  1. 일반 재생목록 행에서 쓰이지 않고 PRO 업로드 취소 버튼에만 남아 있던 `.btn-playlist-remove`를 `.pro-upload-cancel` 하나로 합치고,
  2. 연결된 기기 펼침(`.device-expand-toggle`)·관리자 부여 왕관(`.d-op-btn.administrator-state-button`)·관리자 권한 설정 톱니(`.administrator-action-button`)의 `32px` 호버 원 배경을 없애 모든 목록 행 아이콘을 원 배경 없는 색상 변화(삭제·강퇴·해제·취소는 빨강 `var(--danger-foreground)`, 나머지는 파랑 `var(--primary)`)로 통일하며,
  3. 재생목록 선택 바의 원형 액션 버튼(`.playlist-selection-action`)을 `54px`에서 `56px`로 올려 PR을 열기로 정했다.

## 3. 사용자에게 바뀌는 것 [화면 바뀜]

- **목록 행 아이콘 호버·키보드 포커스**:
  - 운영 9.0.839까지: 재생목록 아이콘은 원 배경 없이 색만 바뀌었으나, 연결된 기기 펼침 화살표(`.device-expand-toggle`)는 `32px` 회색 원(`--surface-3`) + 본문색, 관리자 부여 왕관(`.d-op-btn.administrator-state-button`)은 `32px` 원(`--surface-2`) + 보조색, 관리자 설정 톱니(`.administrator-action-button`)는 `32px` 원(`--surface-2`) + 본문색이었다. 또한 `.administrator-action-button:focus-visible`에 `outline: none`이 있어 키보드 탐색 시 왕관·톱니·권한 해제 X에 공용 포커스 링이 그려지지 않았다.
  - 9.0.840: 모든 목록 행 아이콘이 호버·키보드 포커스 시 원 배경 없이 아이콘 색만 바뀐다(비파괴 액션은 `var(--primary)`, 삭제·강퇴·해제·업로드 취소 X는 `var(--danger-foreground)`, `:disabled` 상태 제외). `.administrator-action-button:focus-visible`의 `outline: none`을 제거해 왕관·톱니·권한 해제 X에도 앱 공용 2px 키보드 포커스 링이 정상 표시된다.
- **PRO 업로드 취소 버튼 클래스 정리**: `src/ui/playlist-view.ts`와 `css/style.css`에서 옛 `.btn-playlist-remove`를 제거하고 `.pro-upload-cancel` 하나로 통합했다. 비활성(`:disabled`) 취소 버튼은 계속 `opacity: 0.32`와 `var(--text-muted)`를 유지한다.
- **재생목록 선택 바 액션 크기**: `.playlist-selection-action`이 `54px × 54px`에서 `56px × 56px`로 커져(컨테이너 `.playlist-selection-bar` 높이 `68px` → `70px`, 여백 포함 공간 `86px`) 앱의 `56px` 컨트롤 높이와 맞춘다. `src/ui/playlist-removal.ts`는 `bar.offsetHeight`를 동적으로 읽으므로 9.0.839의 선택 바 스크롤 공간 계산은 그대로 동작한다.
- **`/designsystem/` 동기화**: `public/editorial-design.css`의 `.playlist-selection-action`, `.expand-toggle`, `.device-expand-toggle`, `.d-op-btn.administrator-state-button`도 앱과 동일하게 맞췄다.
