### A3-R26-C01 — OAuth 복귀 주소의 origin 보존 실패

입력 경로를 정규화한 URL의 origin은 처음에 검사하지만, pathname/search/hash만 다시 저장한다.
이 결과가 이중 슬래시로 시작하면 callback의 두 번째 URL 생성이 이를 외부 authority로 해석한다.
로그인 시작에서 발급한 합성 flow cookie·state를 그대로 사용해 취소 callback까지 연결한 기존 로컬
통합 검사에서 origin 계약 3개가 실패했고, 일반 경로·직접 외부 주소 거절 등 대조 5개는 통과했다.
부모는 원본 실패와 두 URL 생성 지점을 대조했다. 동일 원인의 경로 표기 변형은 1건이다.

외부 provider fetch는 호출되지 않았다. 실제 외부 브라우저 이동·live OAuth·토큰 유출·계정 탈취를
입증한 결과가 아니다. 독립 재실행은 안전 검토 중단 후 수행하지 않았다. 수정 시 정규화 후 저장값과
callback의 최종 목적지 모두 동일 origin을 보장해야 한다.
[부분 실행·원본](../../scratch/qa3-30round-2026-10-09/round-26/report.md).

### A3-R13-C01 — 자연 종료와 다음 재생 사이의 STOP

파일 자연 종료는 idle로 바뀐 뒤 다음 곡 500ms/한 곡 반복 300ms 타이머를 예약한다.
그 사이 등록된 MediaSession STOP을 전달하면 `stopPlayback()`이 idle을 이유로 반환해서 예약을 취소하지 않는다.
부모 Chromium 재실행에서도 다음 곡 또는 반복 곡의 새 오디오 소스가 시작됐다. STOP 없는 정상 진행과
재생 중 STOP 대조는 통과했다. 정지 명령은 아직 실행되지 않은 자동 진행 의도도 취소해야 한다.

실제 WAV·native decode/source·등록된 callback을 사용했지만, 물리 헤드셋/OS가 이 짧은 구간에 STOP을
표시하거나 전달하는 빈도는 검증하지 않았다. [라운드 근거](../../scratch/qa3-30round-2026-10-09/round-13/report.md),
[부모 Chromium 원본](../../scratch/qa3-30round-2026-10-09/parent-adjudication/r13-browser.json).

### A3-R16-C01 — 가득 찬 목록의 YouTube 추가

Standard 호스트가 1000곡 목록에서 URL 또는 검색 결과를 추가하면 입력창부터 닫고 비운다.
이후 실제 queue model이 상한 초과를 거절하지만 오류는 EventBus 로그에만 남고 사용자 안내가 없다.
목록·revision은 그대로이며 입력은 사라진다. 부모의 실제 공개 입력 경로 4개 중 999+1 정상 대조 2개는
통과하고 1000+1의 안내·입력 보존 기대 2개는 다시 실패했다. 입력 소비 전에 수용 여부를 판정해야 한다.

실제 parser/search/queue/EventBus를 연결한 로컬 검사이며 iframe·네트워크·toast 출력 endpoint는 합성했다.

### A3-R18-C01 — 뒤로 이동한 벽시계와 YouTube 보정

정밀 동기화를 마친 게스트의 벽시계를 60초 뒤로 옮기면 실제 SharedClock이 새 PONG으로 재보정돼도
YouTube의 Date.now 기반 cooldown·억제 시각은 남는다. 재동기화가 약 59.5초 밀리고 약 19초 수명의
수동 보정은 적용 전에 만료한다. 입력한 값은 저장되지만 iframe pause/seek/play 명령은 나오지 않는다.
일반 heartbeat 보정도 약 60초 억제됐다. 부모의 0/-60/+60초와 heartbeat 대조 4개에서 동일 현상을 관측했다.

이 검사는 문제 동작을 명시적으로 기대하므로 pass가 결함 해결을 뜻하지 않는다. 실제 시계 모듈·동기화
코드를 사용했지만 OS 시계·실제 iframe·음향은 합성 경계다. 로컬 대기 시간은 단조 시계 또는 명시적인
시계 재기준화와 일관되게 처리할 필요가 있다.
[라운드 근거](../../scratch/qa3-30round-2026-10-09/round-18/report.md),

### A3-R20-C01 — 알려진 채팅 전송 거절 뒤 초안 소실

Standard 게스트의 전송이 동기 예외로 거절되면 실제 `safeSend`/`sendToHost`가 false를 반환한다.
일반 채팅과 귓속말 UI는 이 결과를 반영하지 않아 초안을 비우고 로컬 전송 말풍선을 만든다.
부모의 실제 호스트/게스트 화면에서도 전송 예외를 한 번 주입했을 때 호스트 수신 없이 초안이 사라졌고,
정상 send를 복구한 뒤 새 메시지는 도착했다. PRO의 거절·재시도 대조는 정상이다.

이미 거절을 아는 로컬 전송의 입력·표시 정합성 문제다. 서버 수신 ACK 보장을 새로 요구하는 판정이 아니며,
물리 네트워크 장애의 이벤트 순서는 검증하지 않았다.

### A3-R21-C01 — 짧은 화면 높이의 암호창

### A3-R23-C01 — 백그라운드 재검증과 PWA 갱신

캐시에서 즉시 표시되는 `fouc-cleanup.js`의 백그라운드 재검증 응답을 잡아두면 기존 SW의
`event.waitUntil(cacheUpdate)`가 끝나지 않는다. 다음 worker 설치는 정상 완료돼도 실제 Refresh 승인 후
대화상자만 닫히고 새 controller·문서로 전환되지 않는다. 부모는 지연을 기존 4.5초에서 **12초**로 늘려
기존 v640·waiting installed·새 문서 0을 확인했다. 지연 응답을 해제하면 v641과 정확히 한 번의 reload로
회복했고, 지연 없는 실제 승인 대조도 통과했다.

앱 코드에는 이 재검증 대기 상한이나 승인 후 대기 안내/복구가 없다. 브라우저 자체 최종 network timeout이나
무한 대기를 측정한 것은 아니다. 과거 legacy PWA 단발 정지의 원인을 이 발견으로 소급 확정하지 않는다.
보존된 운영 후보를 로컬에서 서비스하고 SW epoch만 응답에서 바꿨으며 운영은 건드리지 않았다.

### A3-R22-C01 / C02 — 보간 값과 열린 대화상자의 언어

C01: 순차 보간은 삽입된 값 안의 후속 placeholder까지 다시 찾는다. `Song {{position}}`라는 제목은
화면에는 그대로 표시되지만 실제 순서 이동 aria-label에는 `Song 1`이 된다. 부모의 실제 목록 renderer와

한 번 해석해야 하며 사용자 값 자체를 다시 template로 취급하면 안 된다.

C02: 시스템 모드에서 닉네임창을 연 뒤 EN→KO languagechange가 발생하면 배경·html lang·입력 검증은
KO로 바뀌지만 제목·설명·placeholder·버튼은 EN으로 남는다. 실제 dialog 호출자가 번역된 문자열을
snapshot하고 validator는 새 언어를 읽는 차이다. 부모 단위·실제 Chromium 창에서 재현했다.
사용자 지정 literal 문구를 지키는 기존 계약과 번역 가능한 문구의 갱신을 구분해야 한다.

언어 이벤트는 navigator override와 synthetic languagechange로 앱의 실제 등록 handler에 전달했다.

## 확정에서 제외한 관측과 최초 실패

- R05: 취소한 같은 revision을 다시 COMMIT하는 합성 순서는 실제 서버의 pending 삭제·늦은 READY 거절과 맞지 않았다.
- R07: abrupt close의 15초 기대는 실제 30초 RTC grace보다 짧았다. 실제 정리 16.35초, 정상 종료 2.10초로 계약 위반을 입증하지 못했다.
- R10: standalone cancel과 강제 microtask 순서에서 3개 assertion이 실패했다. 실제 caller는 load/queue/connection/session을 먼저 폐기하고, 실제 await 뒤 취소 대조는 통과했다. 원본 실패를 유지하되 결함 수에서 뺐다.
- R11: 임시 preload 21개를 엄격한 20개 상한 위반으로 보려던 가설은 명시 계약·사용자 영향을 입증하지 못했다. bounded cleanup 뒤 0으로 정리됐다.
- R14: native no-argument disconnect의 강제 예외·지원하지 않는 disposer 순서는 실제 native graph 대조에서 재현되지 않았다.
- R16: 넓은 URL ID 추출만으로 잘못된 실제 재생이나 명시된 입력 계약 위반을 입증하지 못했다.
- R20: operator 회수 직후 suggestion 잔상은 남지만 실제 명령이 현재 권한으로 거절되고 다음 입력에 갱신됐다. 권한 결함에서 제외했다.
- R23: old worker에 250ms마다 generation을 묻는 probe 자체가 갱신을 지연했다. native controllerchange 대기 대조로 해소했고 실제 정적 재검증 문제와 구분했다.

그 원인을 적고 scratch만 고쳤다. 실제 계약 실패 기대값을 낮춰 통과시킨 것으로 기록하지 않았다.
