## 15. 지운 주석과 그 뜻 (오너 결정, 2026-11-15)

숨은 시작 화면 워드마크(`44172760`)를 지우며 그 워드마크만 설명하던 `css/style.css`의 주석 셋을 그 주석이 붙은 규칙과 함께 지웠다.

1. 시작 화면 워드마크의 광학 보정: 워드마크를 `translateY(3px)`로 3px 내려 눈으로 맞추되, 그 자리를 이어받는 제목과 설명의 배치는 움직이지 않게 한다는
   뜻.
2. 워드마크 그리기 런타임: 런타임이 정확한 합집합 마스크로 실루엣 하나를 드러내고, 그 선택 런타임이 없으면 정지 로고를 그대로 보이게 둔다는 뜻 (줄인
   움직임에서는 `mask: none`과 짝을 이룸).
3. `--setup-logo-mt: 3px`: 두 열 배치(720 ~ 1279px)에서도 워드마크를 휴대폰과 같은 3px 내려 윗변을 인사 줄에 맞춘다는 결정. 내리지 않으면 2 ~ 3px 위에
   있었고, 크기에 비례해 내리면 26px 태블릿 로고가 너무 내려갔다.

이 밖에 지운 CSS 주석은 없다. 옮긴 주석 둘(`754442f6`)은 글자 그대로 남는 규칙 위로 갔다.

## 19. 하지 않은 것과 확인하지 않은 것

- 실기기(iPhone, iPad, Android)에서 보지 않았다. 대비 높이기와 강제 색, 안전 영역은 Chromium의 흉내다.
- 실제 Chromium 79(옛 TV)에서 돌리지 않았다. 보안 확인 겹, 오른쪽에서 왼쪽 규칙, 겹 id를 걷은 뒤의 승부는 `guard:legacy-tv-build`의 정적 검사와 빌드
  CSS 글자로만 봤다.
- 실제 Windows 고대비에서 보지 않았다. Chromium 흉내의 GrayText와 LinkText는 실제 Windows 팔레트와 색이 다르고, Windows 고대비가
  `prefers-contrast: more`를 함께 알리는지도 확인하지 않았다.
- Safari의 소수 픽셀 반올림(`.98`을 고른 까닭)은 보지 않았다. WebKit 레인은 정수 크기의 회귀만 본다.
- Chromium으로 볼 수 없는 줄: 지운 `-webkit-backdrop-filter: none`(앱 17줄, 공개 7줄), 지운 `-webkit-tap-highlight-color: transparent` 16줄(범용
  규칙은 남음), iOS 홈 화면 앱 모드의 공개 사본 덩어리, 디자인 시스템의 `::-webkit-slider-runnable-track`과 `::-moz-range-track` 사본(첫 사본은 남음),
  빌드에서 꼬리 수가 바뀐 iOS 전용 `@supports (-webkit-touch-callout: none)` 규칙과 `:-webkit-full-screen` 규칙. 초기값이나 남는 규칙이 같은 값을
  준다는 글자 판단뿐이고, 최종 관문의 WebKit 레인(§13.6)은 정해진 모바일 흐름을 돌 뿐 이 값들을 견주지 않는다.
- 오른쪽에서 왼쪽 언어는 아랍어(앱)와 아랍어, 히브리어(About 증명)로만 띄웠고 페르시아어와 우르두어의 실제 글자로는 띄우지 않았다.
- 사진은 다크와 대비 높이기, 강제 색 위주이고 라이트 테마의 오른쪽에서 왼쪽 사진은 없다(계산값은 장면표가 봄). 숨은 워드마크는 따로 찍은 사진 없이
  장면 증명으로 봤다.
- 블로그 글 본문(바깥 피드)과 번역 제안 대기열은 네트워크라 보지 않았다.
- 섞인 버전의 방은 따로 시험하지 않았다(§9).
- 로컬 결과는 exact-main-SHA 후보를 대신하지 않는다.
