## 오너 지시와 결정

- **열차 범위(계획 2026-10-27 작성, 2026-10-28 개정 3).** 9.0.19 UI 묶음이 남긴 넷(V1 숨은 설정 기기 목록 삭제,
  V2 잠긴 음향 설정 그룹의 설명 문장, V3 수동 싱크 패널의 짧은 화면 압축, V4 멤버 내보내기 아이콘의 키보드
  포커스)과 V5(Developer API 재생 영수증 문구)를 싣는다. 처음 계획의 V6(알약 간격)과 V7(계정 두 버튼 한 크기)은
  2026-10-28 오너 결정으로 9.0.19에 들어갔다.
- **영수증 원장 결정 (1)(2)(2026-10-28 아침).** 9.0.18이 남긴 결정 가운데 (1) 사람이 누른 PRO 재생 명령이 원장
  넘침으로 거절되면 기존 토스트 `pro.room_state_limit`을 띄운다(B1). (2) 같은 코드가 재생목록 바이트 예산에서도
  나오는 경우, 재생목록 한도만 기존 `PLAYLIST_CAPACITY_EXCEEDED`('재생목록이 가득 찼어요')로 돌려주고 나머지는
  지금 문구 그대로 두며 진단 이유를 원인별로 나눈다(B2). 그래서 9.0.20은 target `all`이다. (3)은 열차 A(PRO 방
  Worker만, 2026-10-28 22:03 KST 배포)가 맡았고, (4)와 BOT의 24시간 Developer 영수증은 그대로 두고 근거만 적었다(열차
  A의 기록).
- **V2 문장.** 한국어는 '방 관리자만 음향 설정을 변경할 수 있어요.' / '관리자 권한을 확인 중이에요.'(토스트와 같은
  말). 볼륨 그룹은 다른 설명이 없으므로 지금처럼 사유 구절을 설명으로 둔다.
- **V3 C안(2026-10-28 07:4x, 비교 이미지를 보고).** 높이 360px 이하에서 패널 여백을 줄이고, 350px 이하에서는 계정
  창과 같은 알약 44px, 간격 6px, 쌍 위 8px.
- **높이 문턱(2026-10-28 15:0x).** 오너가 앱에 있는 370px 기준을 360px로 낮추면 어떤지 물었다. 그래서 높이 361 ~
  370px에서 로고를 보여도 두 열 사이드바의 탭 다섯이 이름표째 들어가는지 재기로 했다. 들어가면 기존
  `max-height: 370px` 규칙을 360px로 낮추고 V3도 360px을 쓰며, 안 들어가면 V3가 370px을 쓴다. 어느 쪽이든 새
  문턱은 생기지 않는다. 들어갔으므로 360px이다(아래 V3).
- **V4는 넣고 V5는 싣는다.**
- **번역 제안 대기열(V1).** 오너가 2026-10-28 07:5x에 관리자 Translations에서 'No suggestions.'를 봤고, 15:0x에
  Status를 All로 두고 다시 봐도 없었다. 배포 뒤 남은 줄을 거절하는 것은 오너 단계다(운영 데이터라 열차가 하지
  않음).
- **굵기 다섯 역할(2026-10-28 오후).** 앱 전체의 글자 굵기는 제목 700, 고른 항목 700, 같은 목록의 고르지 않은 항목
  500, 이름표(버튼·탭·칩·배지·작은 라벨) 600, 본문과 작은 보조 글 400의 다섯 역할만 쓴다. 관리자 권한 줄의 650은
  600이다. 같은 날 17시대 오너 확인: 두 열 화면의 사이드바 탭(13px)도 고른 것 700, 나머지 500이고, 계정 창 통계
  숫자는 본문 400이며, 칩·데스크톱 설정 탭·아래 탭은 선택 묶음(700 / 500)이다. 코드 입력 숫자(참여 코드, 방 암호
  칸, 수동 싱크 값)를 제목 700으로 둔 것은 오너 결정이 아니라 구현 때 정한 값이다.
- **제목 자간과 커닝(같은 결정).** 제목 자간은 라틴·키릴·그리스 문자 언어가 `-0.02em`, 한글·한중일·태국·인도계·
  아랍·히브리 문자 언어가 0이다(문서 언어의 `:lang()`). 그 밖의 음수 자간은 0으로 하고, 일부러 넓힌 자간은 그대로
  둔다. `font-kerning: normal`을 body에 둔다(Chromium은 기본값에서도 커닝하므로 차이가 없고, 작은 글자의 커닝을
  끄는 Safari만 막음).
- **머리글 로딩 줄(2026-10-29, 9.0.20 미리보기를 보고).** 미디어를 불러오는 동안 로고 자리에 뜨는 머리글 로딩
  줄('준비 중: 파일 이름')이 굵기 역할의 본문 400이면, 로고가 사라진 자리의 글자가 너무 얇고 오른쪽 계정 알약(이름표
  600)과 굵기 차이가 커서 머리글이 지저분해 보인다. 그래서 그 줄만 이름표 600으로 올린다. 9.0.19도 600이었으므로 이
  줄은 운영과 같은 굵기로 돌아간다. 크기, 색, 말줄임, 움직임은 그대로이고 토스트와 다른 상태 줄은 본문 400이다.
- **PRO 방 등록 창 주 버튼(2026-10-28 23시대 승인).** 본문이 '…계정에 이 방을 등록할까요?'라고 물으므로 버튼은
  짧게 '등록'(영어 'Register')이고, 42개 언어 모두 그 언어의 등록 동사로 쓴다(키 `pro.activation_account_continue`).
- **대화상자 나가기(2026-10-28 오후).** 계기는 오너가 본 계정 창의 '로그인 사용 불가' 상태다(다시 시도만 있고 닫기가
  없으며, 바깥을 누르면 닫힘). 기본 정책: 모달은 바깥 클릭·터치로 닫히지 않는다. 나갈 수 있는 상태에는 보이는
  나가기(닫기·취소)가 있고, 두 버튼이면 왼쪽이 나가기, 오른쪽이 행동이다. 조사의 질문에 대한 답은 다음과 같다.
  Esc는 뒤로가기와 같다(맨 위 창만, 그 창의 닫기·취소처럼 닫고, 뒤로가기로 안 닫히는 강제 업데이트와 오디오 복구는
  Esc로도 안 닫힘). '새로고침이 필요해요'는 [닫기 | 새로고침]이다. 2026-10-11 결정 7을 바꾸며, 닫으면 그 기능만 안
  열리고 방은 그대로다. 휴대폰 채팅 시트는 시트라서 바깥 터치 닫기를 두고 왼쪽 위에 보이는 닫기를 더한다. PRO 방
  등록 창은 [취소 | 이 계정으로 계속]과 그 아래 작은 링크 '다른 계정으로 로그인'(언어 창의 '번역 참여'처럼)이고,
  계정이 없으면 [취소 | 로그인]이다.
- **오너가 따로 답하지 않은 질문(같은 날, 열차 쪽에서 정한 기본값).** 세로 쌓임 배치는 F5 뒤 남는 곳이 없어

  있는 `showDialog`를 막는 가드(허용: 오디오 복구, 강제 업데이트).

#### 검토 반영 넷

독립 검토(변경 요청: 중간 1, 낮음 5)를 받아 고쳤다.

- **배경을 누른 뒤의 Esc(중간).** 계정 창, 관리자 권한, 재생목록 전환·트랙 이동, 언어, 수동 싱크, 시그널링 복구는
  Esc 리스너를 창 요소에 붙였다. 배경을 누르면 포커스가 body로 빠져 Esc가 닿지 않았는데 뒤로가기는 닫았다. 이제
  `src/ui/dom.ts`의 `window` 리스너 하나가 아무도 쓰지 않은 Esc(조합 중이 아닌 것)를 뒤로가기가 닿을 맨 위 창에
  넘긴다. 창마다 붙은 Esc 핸들러를 지웠고 미디어 선택과 YouTube 링크 창의 것도 지웠다. 그래서 iOS 셸의 가짜 전체 화면
  영상도 뒤로가기처럼 Esc로 나간다. 화면 보호기, 온보딩 진단, 채팅 시트, `/debug`는 자기 document Esc를 그대로
  쓴다.
- **데모를 끝낼 수 없는 게스트(낮음).** 보이는 나가기와 체험 종료는 첫 구현에서 연결 탭의 [취소 | 확인]을 열었고
  Esc는 아무 일도 하지 않았다. 이제 보이는 나가기, 체험 종료, 4단계 다음, Esc, 뒤로가기가 모두 뒤로가기의 세션
  나가기 확인 [남아있기 | 나가기] 하나를 연다. `back-button-guard`에 `requestLeave()`를 더했고 `app.ts`가
  `ui:request-leave-session`을 받아 부른다. RO-30을 고쳤고 통합 시험 하나를 더했다.
- **새로고침 창을 일부러 닫을 때의 토스트(낮음).** 닫기, Esc, 뒤로가기로 거절하면 '네트워크 오류' 토스트 대신 로그만
  남긴다. 실제 실패의 토스트(대체 문구, 표시 실패, 복구)는 그대로다.
- **수동 싱크 값 편집 중의 Esc(낮음).** Esc가 입력을 버리고 닫던 것을 뒤로가기·완료처럼 값을 반영하고 닫게 했다.
  숫자가 아닌 입력은 지금 값을 지킨다.

F5 한국어 라벨(낮음)은 등록 라벨 증분이 대신했다. 문서끼리 맞지 않던 Esc·`dismissible` 서술(낮음)은 이 보고서와
같은 문서 변경에서 고쳤다.

#### 한계

- 실기기와 WebKit에서는 보지 않았다. 배경을 누른 뒤의 Esc와 방 권한 없는 데모 게스트의 나가기를 다루는 커밋한
  E2E가 없다(jsdom 단위 시험과 위의 개발 서버 확인뿐).
- 계정 창의 '로그인 사용 불가' 상태는 단위 시험, 합성 마크업 측정, 개발 서버 확인으로 봤다.
- 전체 화면 영상은 조사 표에 없었다(Esc 대체 경로로 iOS 셸의 가짜 전체 화면은 Esc로 나감).
- `chat.ts`의 화면 보호기 진입 취소(`cancelOnEscape`)는 `preventDefault`를 부르지 않아 새 대체 경로도 그 Esc를
  본다. 이 열차가 더한 이중 동작은 찾지 못했다(9.0.19부터 있던 것, 선택 후속).

## 사용자가 알아챌 변화

- **창 바깥.** 계정 창(모든 상태), 닉네임 입력, PRO 방 등록 창, 업로드 실패 창, 고정 공지, 관리자 권한 편집 창은
  바깥을 눌러도 닫히지 않는다. 닫기·취소, 뒤로가기, Esc로 닫는다. 휴대폰 채팅 시트만 바깥 터치로 닫힌다. 그래서
  닉네임을 쓰다 바깥을 잘못 눌러 입력을 잃거나, 업로드 실패 창에서 다시 시도할 파일까지 버리거나, 관리자 권한 줄을
  누르다 바깥에서 손을 떼 편집 내용을 잃는 일이 없다.
- **Esc.** 키보드의 Esc가 모든 창에서 뒤로가기와 같다. 맨 위 창 하나만 닫거나 한 단계 뒤로 간다(방 암호 2쪽은
  1쪽으로). 9.0.19에서 Esc에 닫히지 않던 확인 창과 알림도 Esc로 닫힌다(취소로 처리). 강제 업데이트와 '오디오가 잠시
  멈췄어요'는 그대로 열려 있다. 배경을 누른 뒤에도 Esc가 닿는다. 창이 없을 때의 Esc는 아무것도 하지 않는다. 수동 싱크
  값을 고치다 누른 Esc는 값을 반영하고 닫는다(9.0.19는 입력을 버리고 닫음).
- **왼쪽이 나가기.** 계정 창 '로그인 사용 불가'는 [닫기 | 다시 시도](다시 시도 중에도 닫기가 동작). '연결이
  끊어졌어요'는 [돌아가기 | 다시 시작](돌아가기와 뒤로가기는 방을 나가 새로고침, 다시 시작은 게스트를 그 방의 시작
  화면으로). '방장 기기의 응답이 없어요'는 [계속 기다리기 | 세션 나가기](열리자마자 Enter를 눌러도 나가지 않음).
  '새로고침이 필요해요'는 [닫기 | 새로고침](닫으면 그 기능만 열리지 않고 방은 그대로, 오류 토스트 없음). 재생목록
  전환은 [취소 | 확인], 수동 싱크는 [완료 | 초기화], 온보딩 진단은 CLOSE, COPY, REFRESH.

## 바꾸지 않은 것과 오너가 정할 것

1. **등록 라벨의 tr·fr 뜻과 ru 길이.** tr 'Kaydet'와 fr 'Enregistrer'는 본문 질문이 쓰는 동사지만 그 언어에서 흔한
   '저장' 버튼 글과 같다. ru 'Зарегистрировать'는 16자(grapheme)로 가장 길다. F5 뒤 이 창은 두 버튼 줄이라 짧은
   라벨 기준이 14자다. 라벨 시험은 F5 전 전폭 배치의 22자를 보고, 시험 주석도 그 배치를 말한다
   (`src/i18n/__tests__/pro-activation-account-copy.test.ts`). 조립한 bump의 전수 측정(라운드 4)에서는 ru도 320px에서
   한 줄(글자 134px, 칸 160px)이고 42개 언어 모두 짝의 줄바꿈과 넘침이 없다. 시험 기준을 14자로 줄이면 ru가 걸리므로,
   기준을 측정에 맞출지 ru를 줄일지, tr·fr을 그대로 둘지 정한다.
2. **접속 중인 관리자 이름이 색으로만 구분된다.** 굵기 역할로 관리자 목록에서 접속 중인 관리자 이름이 600 → 500이
   되어, 원래 500인 접속하지 않은 관리자와 굵기가 같고 색만 다르다. 굵기나 다른 표시로 다시 구분할지 정한다.
3. **한국어 390px 미디어 고르기 창 제목 두 줄.** 제목 자간 0으로 '재생할 미디어를 선택해주세요'가 390px에서 한 줄 →
   두 줄이 된다(9.0.19도 320 ~ 375px에서는 두 줄). 한국어 제목 고침으로 낱말 가운데서는 끊기지 않는다.
4. **영어 360px 'Center Speaker' 칩.** 기본으로 골라진 역할 칩이 고른 700으로 360px에서 한 줄 → 두 줄이다(약 1px
   모자람. id, ml도 360px, ur은 320px). 가장 작은 고침은 칩 좌우 여백 12 → 11px이나 10px이고 배치 변경이다.
5. **320px 탭 제목 잘림.** 재생목록 탭 머리 제목이 영어 'Playlist'(de, fr, it, pt-br, fil도)에서 0.83px 새로
   잘리고, 한국어 '재생목록'은 잘림이 3.4 → 6.8px로 는다. 선택 개수 제목도 여러 언어에서 더 잘린다. 설정·연결 탭
   머리에서는 넓어진 탭 제목이 초대 코드 버튼을 밀어 pt-br, uk(320 ~ 340px)의 '초대 코드' 이름표가 두 줄이 된다. 모두
   제목 자간 결정의 결과이고, 역할 안에서 고칠 수 있는 손잡이는 자간뿐이다.
6. **두 열 사이드바 시험의 3px 여유.** 새 CI-critical 사이드바 시험은 탭 상자가 계정 배지 위에서 끝나기를 요구한다.
   740x361의 ar, fa, ur에서 여유가 3px이다(Windows Chromium에서 잼, 마지막 탭은 11px 떨어짐). Linux 글꼴로 11px
   아랍어 배지가 3px보다 더 커지면 CI가 실패한다. 조립한 bump의 로컬 critical E2E(Windows, 라운드 3)는 통과했고,
   Linux 실행은 PR CI에서 처음 돈다. 탭 상자의 투명 안쪽 여백 8px 때문에만 실패하면 단언이나 문턱을 다시 본다(말없이
   느슨하게 하지 않음).
7. **9.0.19에서 이어진 일본어 시작 화면 알약(9.0.19 오너 항목 14).** 시작 화면 뒤로 옆 알약의 일본어
   잠시만요(`お待ちください...`)가 320 ~ 347px에서 9.0.18처럼 알약 안에서 두 줄이다. 이 열차는 그 알약을 바꾸지
   않았다. 이대로 둘지, 가운데 정렬을 지키는 다른 방법으로 한 줄을 만들지 정한다.
8. **F6 문구와 겹침.** 다시 시작이 게스트를 방 시작 화면으로 보내므로 `dialog.session_lost_msg`('다시 시작하면 새
   세션을 열 수 있어요')가 맞는지 본다. 방장에게는 두 버튼이 같은 홈 화면에 닿고 로딩 문구만 다르다. 조사의 선택
   항목(같은 게스트에게 `setup.ts`의 방장 끊김 대화상자가 이미 떠 있으면 겹치지 않게)은 하지 않았다.
9. **F7 세션 나가기 색.** 위험 색을 쓸지 정한다(바꾸지 않음).
10. **F10 PRO 입장 뒤 단계.** PRO 입장 경로에서 이 창이 닫힌 뒤 설정 화면에 남는 '비활성 뒤로 + 새로고침'
    단계(`setup-guest.ts`)는 정하지 않았다.
11. **수동 싱크 '완료'를 '닫기'로 바꿀지.** 바꾸지 않았다.
12. **데모 게스트의 확인 창.** 데모를 끝낼 수 없는 게스트의 나가기는 9.0.19의 토스트 대신 뒤로가기의 세션 나가기
    확인([남아있기 | 나가기])을 연다. 연결 탭의 세션 나가기 버튼은 자기 확인([취소 | 확인])을 그대로 쓴다. 기존 키만
    쓰고, PR 설명에서 알린다.
13. **굵기 역할의 나머지 나빠진 곳.** 위 전수 조사의 남은 행이다. 조립한 bump의 전수 측정(라운드 4)에서 받아들인
    경우는 Windows 1,764줄(요소 묶음 29개), Linux 에뮬레이션 2,392줄이고, 받아들인 값보다 더 나빠진 줄은 0이다. 제목 자간(대부분 0 ~ 4px 모자라 두 줄), 고른
    700(설정 칩, 데모 효과 칩, 아래 탭 '설정'의 ml 320px, 데모 단계 알약의 말줄임), 이름표 600(고급 리버브
    슬라이더 이름 두 줄), 연쇄(관리자 권한 줄, 탭 머리의 초대 코드)다. 역할 안에서 안전한 고침은 찾지 못했다. 일본어
    제목의 낱말 가운데 끊김(ja 340 / 360px)은 `word-break: auto-phrase`(Chromium만)가 선택지다. Linux 에뮬레이션에서는
    Pretendard 14px 400이 500보다 넓게 그려지는 글꼴 특성도 있다.
14. **Google 로그인 버튼 500.** Google 표시 규칙 때문에 역할 밖 예외로 남겼다(엄격히는 600).
15. **커닝 범위.** `font-kerning: normal`은 body를 물려받는 글자에만 닿는다. 버튼과 입력 칸은 브라우저 기본 글꼴
    설정 때문에 `auto`로 계산되고 Chromium에서는 같게 그린다. 컨트롤에도 명시하려면 `font-kerning: inherit` 한 줄과
    계약 한 줄이다.
16. **V2 태국어와 원어민 검토.** th의 두 문장 키는 힌트와 같은 값이다. 42개 언어의 새 문장은 원어민 검토가 없다.
    다시 볼 것: en, da, nb, sv, fi, id, ms, es, pt-br, fr, hu의 동명사·명사 꼴, ru·el·bg가 힌트처럼 '설정' 낱말을 뺀 것.
17. **9.0.19에서 이어진 다른 항목.** 이동·복사 창의 아주 짧은 화면 압축, 언어 목록 줄의 라이트 호버, 추천표에서

    남는다. 미리보기가 함께 바꾼 버튼 속 내용·제목·배지(9.0.19 항목 13)는 이 열차의 굵기 역할이 굵기를 정했고

18. **데모 머리글의 트랙 제목 두 줄(조립 뒤 전수 측정에서 찾음).** F11의 나가기(44px와 간격)가 머리글 맨 앞에 늘
    있어 트랙 칸이 390px에서 282 → 226px로 56px 좁아졌다. 그래서 'Linelight OST - Adventure'처럼 긴 트랙 이름이

    않았다.
19. **이번에 처음 잰 창의 제목(같은 측정).** 문자별 제목 자간 규칙(-0.4px → 0)이 9.0.20에서 처음 잰 창에도 닿는다:

    경우(hi, ja, mr, pa, ta, te, zh-hans, zh-hant), Linux 에뮬레이션 21개 경우(gu, hi, ja, ml, mr, ta, zh-hans,

## 섞인 버전과 되돌리기

### 섞인 버전

- App 9.0.19와 9.0.20은 같은 방에서 함께 쓴다. V1 ~ V5, 등록 라벨, 대화상자 나가기, 굵기 역할은 화면, 접근성 설명,
  CSS, 문서만 바꾼다. V1은 설정 쪽 구독만 지웠고 `DEVICE_LIST_UPDATE` 메시지와 상태 모양은 그대로다.
- B1은 9.0.20 탭에만 있는 안내다.
- B2: 바닥 787 이상의 모든 App은 재생목록 경로에서 `PLAYLIST_CAPACITY_EXCEEDED`를 이미 '재생목록이 가득
  찼어요'로 보인다. Developer API와 BOT의 답은 그대로다.
- 배포 중: 릴리스는 PRO 방 Worker를 먼저 배포한다. 옛 App과 새 PRO 방 Worker, 새 App과 옛 PRO 방 Worker가 만나도
  B1 토스트와 위 사상이 그대로 동작한다(원장 넘침은 양쪽 모두 `ROOM_STATE_CAPACITY_EXCEEDED`).
- signaling은 진단 파일 때문에 다시 배포된다. Durable Object가 다시 시작해 열린 Standard 방이 신호 연결을 한 번
  다시 잇고, 최소 빌드 787 아래 방장은 재연결에서 거절된다(9.0.18과 같음).

### 되돌리기

- 기본은 hotfix 절차대로 더 높은 SemVer와 캐시 epoch의 코드 되돌리기다(9.0.21 / v794 이상).
- 실패한 `all` 실행의 자동 복구는 릴리스가 배포한 Worker를 checkpoint의 직전 버전으로 되돌린다. 직전 운영은 App
  9.0.19 `5a4284d6`, PRO 방 열차 A `a04acac1`, remote-share `1056e44d`, signaling `60343a64`, Developer API facade
  `f54a224b`, Developer API `51ca7da5`다. 이 열차는 계약 표지, forward floor, 바닥을 더하지 않으므로 그 복구를 막지
  않는다. 이 릴리스의 checkpoint는 배포 뒤 기록 PR이 적는다.
- PRO 방 Worker만 열차 A(`a04acac1`)로: 재생목록 한도가 다시 '잠시 후' 문구가 되고 진단 이유가 `core`로 돌아간다.
  B2는 저장 모양과 저장 값을 바꾸지 않는다(이유는 오류 객체와 진단 로그에만 있음). 그래서 커밋한 되돌리기 시험은
  두지 않았다.
- App만 9.0.19(`5a4284d6`)로: 저장 바닥 787 ≤ 792라 `lower` 없이 된다. B1 안내, V1 ~ V5, 등록 라벨, 대화상자
  나가기, 굵기 역할이 9.0.19로 돌아간다. 통신 모양은 같다.
- signaling을 되돌리거나 다시 배포하면 Standard 방이 다시 연결된다.
- 새 D1, 비밀, 바인딩, Wrangler 설정, CORS, 계약 표지, 저장 키, 저장 데이터 모양은 없다. 릴리스 준비에서 origin/main과
  bump 사이를 다시 봤다: `cloudflare/`에서 바뀐 것은 `pro-room-worker.ts`, `pro-room-diagnostics.ts`와 bump의
  `app-worker.ts` 한 줄이고, `wrangler.*.toml`, D1 migration, 의존성은 그대로다(`package.json`과
  `package-lock.json`은 버전 줄만).
